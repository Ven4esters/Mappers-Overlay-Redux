# ADR-0018: диагональ лежит в локальной плоскости `X/Z` и поворачивается на `RX`

Статус: принято (1.5.3). Заменяет ADR-0017 (там локальная диагональ была в плоскости
`Y/Z`, и числа с примером пользователя не сходились).

## Контекст

Три предыдущих варианта давали расхождение на нетипичных углах:

| Версия | Формула | Что не так |
| --- | --- | --- |
| 1.4.x | `ΔY = dy·шаг`, `ΔZ = dx·шаг` | фиксированные 45°, угол вообще не участвует |
| 1.5.1 | `ΔY = ay·cos RX`, `ΔZ = ax·sin RX` | компоненты «по наклону», а не поворот |
| 1.5.2 | `P + Rx(RX)·(0, ay, ax)/√2` | шаг живёт в плоскости `Y/Z`, числа не совпали с расчётом |

Пользователь прислал расчёт (`P_new = P + Rx(θ)·Δ_local`, матрица `Rx`, две раскладки —
`X/Y` и `X/Z`) и контрольный пример:

> `x = −1849.342, y = 416.528, z = 128.826`, `RX = 37°`, шаг `2.0`
> → `y = 415.676`, `z = 129.955`

## Проверка примера

```
ΔY = 415.676 − 416.528 = −0.852 = −(2/√2)·sin 37°
ΔZ = 129.955 − 128.826 = +1.129 = +(2/√2)·cos 37°
обратный поворот на −37°: Δ_local = (0.000, 1.414) = (0, L/√2)
```

То есть по `Y`/`Z` локальное смещение нулевое, а вся величина сидит в `Z_local = L/√2`.
Диагональ не может состоять из одной оси — значит вторая компонента лежит по `X`, и это
ровно вторая раскладка из письма: **диагональ в локальной плоскости `X/Z`**.

Дополнительная проверка: `√(0.852² + 1.129²) = 1.414`, а шаг — `2.0`. Разница ровно в `√2`
раза, и она закрывается компонентой `ΔX = ±L/√2`. С ней длина шага снова равна шагу, а
клавиши «вверх-вправо» и «вверх-влево» перестают быть одинаковыми.

## Решение

```
Δ_local = (±L/√2, 0, ±L/√2)          |Δ_local| = L

X_new = X + Δx
Y_new = Y + Δy·cos θ − Δz·sin θ  =  Y − Δz·sin θ
Z_new = Z + Δy·sin θ + Δz·cos θ  =  Z + Δz·cos θ
```

(`θ = RX`, `Δy = 0`)

| Клавиша | `Δ_local` | `RX = 0°` | `RX = 37°` | `RX = 45°` |
| --- | --- | --- | --- | --- |
| `Num 9` вверх-вправо | `(+L/√2, 0, +L/√2)` | `X +0.354, Z +0.354` | `X +0.354, Y −0.213, Z +0.283` | `X +0.354, Y −0.250, Z +0.250` |
| `Num 7` вверх-влево | `(−L/√2, 0, +L/√2)` | `X −0.354, Z +0.354` | `X −0.354, Y −0.213, Z +0.283` | `X −0.354, Y −0.250, Z +0.250` |
| `Num 1` вниз-влево | `(−L/√2, 0, −L/√2)` | `X −0.354, Z −0.354` | `X −0.354, Y +0.213, Z −0.283` | `X −0.354, Y +0.250, Z −0.250` |
| `Num 3` вниз-вправо | `(+L/√2, 0, −L/√2)` | `X +0.354, Z −0.354` | `X +0.354, Y +0.213, Z −0.283` | `X +0.354, Y +0.250, Z −0.250` |

(шаг 0.5 м)

## Почему так

* **Совпадает с контрольным примером**: при `L = 2`, `RX = 37°` получается
  `Y = 415.677`, `Z = 129.955`; расхождение в 0.001 — округление координат до миллиметра.
* **Длина шага равна шагу** при любом угле: `|Δ_local| = L`, поворот длину не меняет.
* **Шаг живёт в осях предмета**, поэтому копии, поставленные подряд, не расходятся —
  обратный поворот на `−RX` возвращает ту же `Δ_local` (тест
  `test_diagonal_keeps_its_local_direction_at_any_angle`).
* **Клавиши различимы**: `Num 9` и `Num 7` отличаются знаком `ΔX` (вперёд/назад), а не
  только знаком `Y`. Противоположные клавиши гасят друг друга по всем трём осям.
* **`RZ` по-прежнему не участвует** (ADR-0014): диагонали не крутятся вместе с поворотом
  вокруг вертикали.

## Следствия

* Диагонали теперь меняют `X` (глубину) на `±шаг/√2`. Это осознанно: без `X` шаг по `Y/Z`
  короче шага в `√2` раза, а «вверх-вправо» и «вверх-влево» совпадают. Прямые клавиши
  `Num 8/2/4/6` и режим высоты `X` не трогают, как и раньше.
* При `RX = 0` диагональ идёт по `X` и `Z` — «вперёд-вверх» и «вперёд-вниз».
* В журнале и строке состояния у диагонального шага теперь три записанных поля: `X, Y, Z`.
