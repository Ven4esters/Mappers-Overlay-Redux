# ADR-0001: слоистая архитектура

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

## Контекст

Приложение одновременно работает с тремя нестабильными вещами: игровым клиентом (окно,
фокус, панель LSP), Win32 (клики, клавиши, буфер обмена) и пользователем. Если всё это
смешать в одном окне, любую ошибку в математике сдвига приходится проверять мышью в игре.

## Решение

Четыре слоя, зависимости только внутрь:

- `domain/` — чистая логика: `Pose`, `Field`, `Direction`, `shifted()`, разбор и
  форматирование чисел. Без Qt, ctypes, файлов и времени.
- `application/` — сценарии: `MappingSession` (считать, шаг), `PoseWriter`
  (что записать и как проверить), порты в виде `Protocol`.
- `infrastructure/` — Win32 ввод, системный буфер, JSON-настройки, автоматизация панели.
  Реализует порты, ничего не решает про направления.
- `ui/` — PySide6: вкладки, стили, фоновые задачи. Знает про application, не про Win32.

## Последствия

- Математику сдвига и запись можно тестировать без игры: тестам достаточно фейкового
  ввода и фейкового буфера.
- Замена способа обмена с панелью (например, горячие клавиши вместо кликов) не трогает
  домен и UI.
- Цена — больше файлов и явные порты; для приложения на 3 тысячи строк это оправдано.
