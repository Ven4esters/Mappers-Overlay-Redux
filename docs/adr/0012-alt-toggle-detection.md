# ADR-0012: как ловится одиночное нажатие `Alt`

## Контекст

Пользователь сообщил: «простого нажатия `Alt` недостаточно для включения режима, сам не
понял, как смог его включить, повторное нажатие не отключает режим». В журнале за сессию
строка «Alt нажат один: переключаю режим наклона» встречается ровно один раз, а режим
после этого остался включённым навсегда.

Причин оказалось две, обе в обработчике низкоуровневого хука
`map_overlay/infrastructure/hotkeys.py`:

1. **Код клавиши.** Проверка была `vk == VK_MENU` (`0x12`), но `WH_KEYBOARD_LL` присылает
   конкретную клавишу: `0xA4` (`VK_LMENU`) для левого `Alt` и `0xA5` (`VK_RMENU`) для
   правого. Условие срабатывало случайно.
2. **Свои клавиши.** Обмен с панелью посылает `Ctrl+A`/`Ctrl+V` через `SendInput`; они
   возвращаются в собственный хук. Нажатие `Ctrl` между нажатием и отпусканием `Alt`
   сбрасывало флаг «нажат один», поэтому переключение терялось во время работы.

## Решение

* `domain/keynames.py` получает `generic_vk`: `0xA0`/`0xA1` → `Shift`, `0xA2`/`0xA3` →
  `Ctrl`, `0xA4`/`0xA5` → `Alt`. Хук приводит `data.vk` до всех проверок, поэтому одна
  нормализация чинит и переключатель наклона, и переназначаемые горячие клавиши.
* `KBDLLHOOKSTRUCT.flags & LLKHF_INJECTED` (`0x10`) — свои клавиши не участвуют в логике
  «одиночного нажатия».
* Дополнительно режим можно включить галочкой на вкладке «Движение»: если игра или
  система забирают `Alt`, у пользователя остаётся способ без клавиатуры.

## Что не меняется

`Alt` по-прежнему **не забирается** у игры: хук только наблюдает. Комбинации (`Alt+Tab`,
`Alt+F4`, `Alt+Num 8`) режим не переключают — это важно, иначе режим менялся бы во время
обычной работы. Привычка «`Alt` + направление» тоже сохранена.
