# ADR-0051. Токен самозаписи: не сверять панель после своей же записи

- Статус: принято
- Дата: 2026-11-19
- Владелец: @Ven4esters
- Пересмотр: 2027-11-19
- Версия: 1.25.0

## Контекст

Перед каждой записью `PoseWriter` перечитывал поле `X` и сравнивал его с позой в памяти:
так оверлей понимает, что панель показывает уже другое значение (его вписали руками, панель
переоткрылась, выбран другой предмет), и не затирает чужое. Проверка стоит одного обмена через
буфер обмена — около 0.16 с на шаг.

Сразу после своей же записи эта проверка бессмысленна: значение в панели только что поставил сам
оверлей, и память о нём — источник истины. При шагах подряд (а это обычный режим работы: нажал
`Num 4` несколько раз) сверка срабатывает снова и снова, съедая почти треть времени шага.

## Варианты

1. **Ничего не менять.** Надёжно, но каждый шаг платит 0.16 с за проверку, которая после своей
   записи всегда проходит.
2. **Убрать сверку совсем.** Быстро, но оверлей начнёт затирать значения, вписанные в панель
   руками, и считать от неверных координат — именно от этого защищала проверка.
3. **Сверять только `X` перед первой записью серии.** Серия заканчивается только по времени, а
   не по действию пользователя: «первую запись» пришлось бы определять по паузе, и пауза всё равно
   осталась бы, просто спрятанной.
4. **Токен самозаписи с паузой.** После успешной записи оверлей запоминает время и записанную позу;
   следующая сверка пропускается, пока пауза не истекла и поза в памяти совпадает с токеном.

## Решение

Выбран вариант 4.

- `PoseWriter` получает `self_write_grace` (по умолчанию 2 с, допустимо 0…10) и часы — их можно
  подменить в тестах.
- После записи сохраняется `(время, целевая поза)`. Перед следующей записью сверка пропускается,
  если пауза не истекла **и** поза в памяти не разошлась с токеном: расхождение означает, что
  координаты сменились другим путём («Считать», другой предмет), и проверка нужна как обычно.
- `self_write_grace = 0` возвращает прежнее поведение: сверка перед каждой записью.
- Настройка «Не сверять панель сразу после своей записи» включает паузу из окна настроек;
  ключ файла — `self_write_grace`.

## Последствия

- Шаг подряд перестаёт перечитывать `X`: пауза прямого шага падает примерно с 0.51 до 0.35 с.
- Защита ослабевает в одном окне: если предмет подвинули в игре в те же 2 секунды после записи,
  оверлей этого не заметит до следующей сверки. Окно короткое, а запись всё равно идемпотентна;
  пауза ограничена сверху (10 с), чтобы «токен» не жил долго.
- Чужое изменение, попавшее в память оверлея (например, «Считать» после правки), ловится сразу:
  токен сверяется и с позой, а не только со временем.
- Проверка после записи (`verify`) не меняется: каждая записанная координата по-прежнему
  перечитывается.

## Откат

Убрать `self_write_grace` из `PoseWriter` и `Settings`, вернуть безусловный вызов
`_check_panel_matches` в `write_changes`. Тесты `tests/test_writer.py` (блок «токен самозаписи»)
описывают поведение, которое при откате должно исчезнуть.
