# ADR-0006: безопасность перехвата клавиатуры

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

## Контекст

В 1.1.0 перехват был удобным, но слишком «широким»: режим записи привязки забирал все
клавиши, пока не получит нажатие, а окно оверлея при запуске забирало фокус у игры.
Пользователь сообщил: «при включённом оверлее в игре пропадает управление клавиатурой».

Причина складывается из трёх вещей:

1. окно активировалось при `show()`, и игра переставала получать клавиши, пока фокус не
   вернут кликом;
2. запись привязки не имела ни таймаута, ни отмены по потере фокуса — уйдя в игру, человек
   продолжал жить с «перехвачено всё»;
3. любая ошибка внутри хука (`ctypes` возвращает 0 при исключении) могла превратиться в
   «клавиша не дошла никуда».

## Решение

1. **Окно не активируется при показе**: `WA_ShowWithoutActivating`. Клик по оверлею
   активирует его явно — это осознанное действие пользователя.
2. **Запись привязки ограничена окном**: вне окна оверлея клавиши не перехватываются даже
   в режиме записи; потеря фокуса и таймаут 10 с отменяют запись.
3. **Хук не блокирует по ошибке**: `try/except` вокруг обработчика, при сбое — пропуск
   клавиши и одна запись в журнал.
4. **Отпускание — только после перехваченного нажатия**: игра не получает «зажатую»
   клавишу.
5. **Аварийный выход мышью**: галочка «Перехватывать клавиши у игры» выключает перехват
   на лету. Мышь хук не трогает, поэтому выход доступен всегда.
6. **Предупреждение об игровых клавишах**: `W`, `A`, `S`, `D`, `Space`, `Shift`, `Ctrl`,
   `Tab`, `Esc` назначать можно, но оверлей честно говорит, что игра их больше не получит.

## Последствия

- Горячие клавиши по-прежнему работают при активной игре — это их смысл.
- Пока окно оверлея активно, назначенные клавиши всё равно забираются: так пользователь
  может нажать `Num 8`, стоя в настройках.
- Нумерация в полях ввода цифрового блока при активном окне оверлея перехватывается
  назначенными клавишами; это осознанный компромисс, снимается галочкой.
