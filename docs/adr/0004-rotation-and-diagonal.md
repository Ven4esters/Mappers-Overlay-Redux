# ADR-0004: поворот RZ и диагональ «шаг по прямой»

## Контекст

Пользователь проверил 1.0.0 в игре и уточнил две вещи:

1. `RZ` растёт против часовой стрелки и уменьшается по часовой. При повороте на 90°
   «вперёд» должно вести вдоль повёрнутого предмета, а не по мировому `−X`.
2. Шаг должен быть шагом: нажав диагональ при шаге 5 м, предмет обязан пройти 5 м, а не
   7.07 м. Прежняя версия меняла каждую ось на полный шаг.

## Решение

1. Направление — единичный вектор `(dx, dy)` в системе предмета:
   вперёд `(−1, 0)`, назад `(1, 0)`, влево `(0, −1)`, вправо `(0, 1)`,
   диагонали — сумма соседних.
2. Диагональ нормируется: `(±1, ±1) / √2`, поэтому длина вектора всегда 1.
3. Вектор поворачивается на `RZ` по правилу «плюс — против часовой»:
   `x' = x·cos − y·sin`, `y' = x·sin + y·cos`.
4. Смещение: `X += x'·шаг`, `Y += y'·шаг`, округление до 3 знаков.
5. `RX`/`RY` (наклон) на движение не влияют: предмет движется в горизонтальной плоскости,
   о чём UI предупреждает, когда наклон ненулевой.

## Проверки

- `rz = 90°`, вперёд: `X` не меняется, `Y` увеличивается на шаг.
- `rz = −90°`, вперёд: `Y` уменьшается.
- Диагональ при любом `RZ`: `hypot(ΔX, ΔY) = шаг` с точностью до миллиметра округления.
- `rz = 0`: таблица из README не изменилась.

## Последствия

- Тесты фиксируют и таблицу при нуле, и поворот: `test_movement.py`.
- Если в игре знак окажется обратным, правится одна константа в `_rotate` и тесты-эталоны,
  а не логика целиком.
