# ADR-0007: знаки направлений уточнены по игре

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

## Контекст

В 1.0.0 знаки были взяты из словесного описания пользователя: «вперёд — `X` в минус,
влево — `Y` в минус». Проверка в игре в 1.1.2 показала обратное: при `RZ = 0` все восемь
направлений зеркальны — «вперёд» уводило предмет назад, «влево» — вправо, диагонали
разъезжались так же.

Ошибка не в коде, а в исходных данных: код точно реализовал то, что было сказано словами.
Поэтому истиной объявлена игра, а не формулировка.

## Решение

Базовые векторы при `RZ = 0`:

| Направление | Клавиша по умолчанию | Вектор |
| --- | --- | --- |
| Вперёд | `Num 8` | `(1, 0)` |
| Назад | `Num 2` | `(-1, 0)` |
| Влево | `Num 4` | `(0, 1)` |
| Вправо | `Num 6` | `(0, -1)` |
| Вперёд-влево | `Num 7` | `(1, 1) / √2` |
| Вперёд-вправо | `Num 9` | `(1, -1) / √2` |
| Назад-влево | `Num 1` | `(-1, 1) / √2` |
| Назад-вправо | `Num 3` | `(-1, -1) / √2` |

Поворот `RZ` остаётся прежним: `+RZ` — против часовой, вектор поворачивается матрицей
`(x·cos − y·sin, x·sin + y·cos)`.

## Проверки

- `tests/test_directions.py` — таблица векторов.
- `tests/test_movement.py` — таблица итоговых координат и поворот `RZ`.
- `tests/test_ui.py::test_numpad_directions_match_the_game` и
  `test_numpad_diagonals_match_the_game` — путь «клавиша → действие → панель» для всех
  восьми клавиш, ровно как проверял пользователь.

## Последствия

- Смена знаков — это одна таблица `_AXES` в `domain/directions.py`; тесты фиксируют её
  дважды: на уровне домена и на уровне клавиш.
- Направление поворота при `RZ ≠ 0` пока не проверено в игре. Если при повороте предмета
  направления поедут не туда, правится знак матрицы в `_rotate` и таблица поворотов в
  тестах — но не базовая таблица.
