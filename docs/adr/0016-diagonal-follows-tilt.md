# ADR-0016: диагонали идут по наклону предмета (`RX`)

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

Статус: **заменено в 1.5.2 (ADR-0017).** Здесь шаг считался «по наклону»
(`ΔY = ay·cos RX`, `ΔZ = ax·sin RX`); на 37° предмет всё равно съезжал, потому что шаг не
поворачивался в осях предмета. Оставлено как история решения.

## Контекст

ADR-0014 закрепил диагонали в координатах экрана жёсткими 45°:

```
ΔY = dy · step,  ΔZ = dx · step,  ΔX = 0
```

Такая формула верна только при `RX = 45°` (там «линия к линии» совпадает с плоскостью
предмета) и при `RX = 90°` (диагональ вырождается в чистую ось). Пользователь описал
поведение при `RX = 37°`, `RZ = 0`:

> Сдвиг плохо работает с нетипичными углами по типу 37 градусов. Сдвиг происходит с
> искажениями, а не ровно стенка линия к линии, как это происходит с 45 и 90 градусами.
>
> Он должен идти как при 45 градусах, идти ровно. Например, при движении вправо-верх по
> итогу он уходит вправо и ниже, хотя Z при этом растёт, а Y уходит в минус.

Причина искажения: шаг не зависит от наклона. Поверхность при `RX = 37°` наклонена на
37°, а шаг идёт под 45° — предмет уезжает с линии поверхности, и вместо «стенка к стенке»
виден клин. Подгонять коэффициенты под 45° бессмысленно: нужна зависимость от угла.

## Решение

Компоненты диагонали берутся из угла наклона предмета:

```
ΔX = 0,  ΔY = ay · cos(RX) · step,  ΔZ = ax · sin(RX) · step
```

где `(ax, ay)` — экранные оси клавиши (`ax` — «вперёд/назад», `ay` — «влево/вправо»):

| Клавиша | `(ax, ay)` | При `RX = 45°` | При `RX = 37°` | Куда идёт на экране |
| --- | --- | --- | --- | --- |
| `Num 9` | `(1, −1)` | `Y −0.354, Z +0.354` | `Y −0.399, Z +0.301` | вверх-вправо |
| `Num 7` | `(1, 1)` | `Y +0.354, Z +0.354` | `Y +0.399, Z +0.301` | вверх-влево |
| `Num 1` | `(−1, 1)` | `Y +0.354, Z −0.354` | `Y +0.399, Z −0.301` | вниз-влево |
| `Num 3` | `(−1, −1)` | `Y −0.354, Z −0.354` | `Y −0.399, Z −0.301` | вниз-вправо |

(шаг 0.5 м; `cos 37° = 0.399`, `sin 37° = 0.301`)

## Почему так

* Наклон шага на экране равен наклону предмета: `ΔZ / (−ΔY) = tan(RX)`. Это и есть
  «линия к линии» — при любом угле, а не только при 45°.
* При `RX = 45°` формула даёт ровно прежние числа (`0.354 / 0.354`), поэтому привычное
  поведение сохраняется; при `RX = 90°` — чистую вертикаль, как и раньше.
* Длина шага не меняется: `cos² + sin² = 1`, поэтому предмет проходит ровно `step`, а не
  `step · √2`. Проверяется тестом `test_diagonal_length_is_exactly_one_step`.
* Остаётся прежняя независимость от `RZ` (ADR-0014): поворот вокруг вертикали не меняет
  наклон поверхности. `test_diagonal_does_not_depend_on_rotation`.
* `X` не трогается: диагональ — движение в видимой плоскости предмета, глубина — у прямых
  клавиш.

## Следствия

* На ровном предмете (`RX = 0`) вертикальной составляющей нет: диагональ ложится в
  горизонталь по `Y` (`ΔZ = 0`). Это осознанно — у плоской поверхности нет «верха», и
  подмешивать `Z` значило бы снова отрываться от линии. Тест
  `test_diagonal_on_a_flat_object_is_horizontal`.
* При отрицательном `RX` знак `ΔZ` следует за наклоном: поверхность опускается вправо —
  и шаг опускается. Ключ по-прежнему называется «вверх-вправо», но идёт по поверхности;
  в этом и смысл привязки к плоскости. `test_negative_tilt_turns_the_diagonal_with_the_surface`.
* Для «поднять и подвинуть» по-прежнему есть режим высоты (`Alt`, ADR-0015): он меняет `Z`
  напрямую и от углов не зависит.
* `RY` в формуле не участвует: предметы в работе маппера наклоняются по `RX`, а крен по
  `RY` оставлен как есть.
