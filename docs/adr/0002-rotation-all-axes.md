# ADR-0002. Движение в локальных осях пропа, включая наклоны

**Дата:** 2026-11-22
**Статус:** принято

## Контекст

Мапперы двигают пропы вдоль стен и прижимают их друг к другу без зазоров. Проп повёрнут на
произвольный угол `RZ`, иногда ещё и наклонён (`RX`, `RY`). Кнопки «влево/вправо/вперёд»,
которые двигают по мировым осям, в этом случае уводят объект не туда, и приходится подгонять
координаты вручную.

Пользователь отдельно попросил: угол поворота учитывается, сдвиг идёт сразу по двум осям;
движение должно быть предсказуемым.

## Решение

- Направления задаются в **локальных** осях предмета: `+X` вправо, `+Y` вперёд, `+Z` вверх.
- Мировой сдвиг: `world = M · local · step`, где `M = Rz · Ry · Rx` — та же
  последовательность, в которой GTA V применяет углы к пропу.
- Восемь направлений в плоскости `XY` (включая диагонали) и два по `Z`. Диагоналей в
  пространстве `Z` нет: они не нужны для стыковки по полу/стене и удваивают число кнопок.
- Наклоны `RX`/`RY` учитываются по умолчанию (движение по плоскости предмета), но
  отключаются в настройках — тогда двигаем строго по полу.
- Длина диагонали по умолчанию равна шагу (компоненты делятся на `√2`); переключатель
  «по шагу на каждую ось» доступен для тех, кто стыкует по сетке.

## Последствия

- «Вперёд» при `RZ = 90°` уводит на запад — это и есть движение вдоль собственной оси.
- Углы нормализуются к `[-180°, 180°)`, как в панели игры: `170° + 20° = -170°`.
- Проверено тестами на матрицу (`tests/test_geometry.py`) и на движение (`tests/test_movement.py`).
