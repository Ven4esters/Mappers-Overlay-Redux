# ADR-0044. Стандарты команды: правила, которые проверяет машина

- Статус: принято
- Дата: 2026-11-19
- Владелец: @Ven4esters
- Пересмотр: 2027-11-19
- Версия: 1.22.0

## Контекст

Проект жил по инструкции `docs/instruction-code-style-and-checks.md`, но три тома команды —
«Инженерный стандарт», «Настольная книга UI/UX» и «README под ключ» — добавляют пласты, которых
в инструкции нет: политика исключений с храповиком, CODEOWNERS и владение, шаблоны issue и ADR,
SBOM и SLA на уязвимости, проверка документации в CI, измеримая доступность интерфейса.

Главный тезис стандарта: правило, которое нельзя проверить линтером, тестом или CI, будет
нарушаться. Значит, принять документы «к сведению» недостаточно — каждое требование нужно либо
автоматизировать, либо явно записать как отклонение с владельцем и сроком.

Второе наблюдение — дефекты, которые копились без автоматики: README отставал от кода на четыре
версии (утверждал 1.17.0 при 1.21.0), ссылка на иконку в ADR-0038 вела внутрь `docs/adr/docs/`,
у ADR не было владельца и срока пересмотра, а ни один документ не проверялся на битые ссылки.

## Рассмотренные варианты

1. **Только описать правила в CONTRIBUTING/STYLEGUIDE.** Плюс: быстро. Минус: ровно то, от чего
   предупреждает стандарт — правило без проверки живёт неделю и исчезает.
2. **Подключить готовые сервисы (markdownlint, lychee, Codecov, Dependabot).** Плюс: знакомые
   инструменты. Минус: новые зависимости и сетевые действия в CI, а часть проверок (версия в
   README, владелец ADR, срок исключения) готовые инструменты не умеют вовсе.
3. **Свои маленькие проверки на Python + существующие линтеры.** Плюс: проверки понимают
   предметную область (русские заголовки и якоря, версия приложения, формат ADR), работают
   офлайн и тестируются тестами. Минус: свой код надо поддерживать.
4. **«Ничего не делать».** README продолжит отставать, а исключения — становиться вечными.

## Решение

Выбран вариант 3: правила автоматизируются там, где это возможно без новых зависимостей.

- `tools/check_docs.py` — относительные ссылки, якоря (включая кириллицу), alt-тексты,
  обязательные разделы README, совпадение версии в README и в приложении, наличие владельца и
  срока пересмотра у каждого ADR.
- `tools/check_exceptions.py` — таблица исключений в `docs/quality/exceptions.md`: причина,
  владелец, срок, статус; просроченное исключение ломает CI.
- `tools/make_sbom.py` — SBOM в формате CycloneDX на каждую сборку, прикладывается артефактом.
- `.pre-commit-config.yaml` — те же проверки локально, `repo: local`: хуки вызывают уже
  установленные `ruff`, `mypy` и наши инструменты, без скачивания окружений.
- ruff: включены правила сложности (`C901`, `PLR0912`, `PLR0913`, `PLR0915`); порог числа
  параметров — 7 с записанным исключением для конструкторов с внедрением зависимостей.
- Доступность стала измеримой: `tests/test_theme.py` проверяет контраст текста по WCAG AA,
  видимый фокус в QSS и доступные имена кнопок-стрелок; у стрелок появилась зона клика 62×48 px.
- `CONTRIBUTING.md`, `STYLEGUIDE.md`, `SECURITY.md`, `CODEOWNERS`, шаблоны issue и PR, шаблон ADR
  и README приведены к структуре из книг.

Правило остаётся в силе, пока его проверяет CI. Если проверка мешает чаще, чем ловит дефекты, она
пересматривается на квартальной ревизии, а не отключается молча.

## Последствия

- **Проще:** новый участник поднимает проект по README и видит те же требования, что проверяет
  CI; битые ссылки и устаревшая версия ловятся до мержа; исключения не живут вечно.
- **Дороже:** каждое изменение документации проходит `check_docs`; при переименовании заголовка
  нужно обновить якоря. Версия в README — обязательная строка, её правит релиз.
- **Немедленно:** проверки включены в `ci.yml` и в pre-commit; README переписан по структуре
  витрины; ADR-0038 исправлен, всем ADR добавлены владелец и дата пересмотра.
- **Отложено:** mutation testing и SBOM-подпись артефактов — для настольной утилиты с одним
  мейнтейнером выгода ниже стоимости; вернуться к вопросу на пересмотре 2027-11-19.
- **Откат:** проверки — отдельные команды; чтобы вернуть прежний режим, достаточно убрать шаг из
  `ci.yml` и хуки из `.pre-commit-config.yaml`. Данные и поведение приложения не затронуты.
