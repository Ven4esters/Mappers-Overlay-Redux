# ADR-0047. exe в релизе: контрольные суммы, VirusTotal и честный TODO в README

- Статус: принято
- Дата: 2026-11-19
- Владелец: @Ven4esters
- Пересмотр: 2027-11-19
- Версия: 1.23.5

## Контекст

Заказчик попросил, чтобы README давал человеку три вещи: место, где написано, как скачать `.exe`
из релиза; данные для проверки скачанного файла (MD5, SHA256) и ссылку на отчёт VirusTotal; и
инструмент, который эти данные готовит, чтобы они не переписывались руками.

Сейчас ни одного из трёх нет. `MappersOverlayRedux.exe` собирается `build_exe.bat`, ложится в
`dist\MappersOverlayRedux` и никуда не публикуется: раздел Releases пуст (`ADR-0046`), README
предлагает «скачать папку проекта целиком (или клонировать репозиторий)». Контрольных сумм нет
вовсе, упоминаний VirusTotal — тоже. При этом PyInstaller-сборка — это сотни файлов и `_internal`,
и пользователь, скачавший архив, не имеет никакого способа убедиться, что файл не подменён по
дороге. SmartScreen при этом ругается на неизвестного издателя (пункт 23
[плана улучшений](../IMPROVEMENT-PLAN.md)).

Вторая половина проблемы — README, который врёт. Заполнить таблицу «примерными» числами проще
всего, и она будет выглядеть убедительно; но каждый, кто скачает файл, получит несовпадение сумм и
решит, что сборка заражена. Поэтому в README до появления файла должны стоять честные «нет» и
`TODO`, а не правдоподобные цифры.

## Рассмотренные варианты

1. **Заполнить таблицу правдоподобными числами сейчас.** Дёшево и красиво, но это ложь в
   документе, который люди используют для проверки безопасности файла. Отвергнуто.
2. **Молчать до появления первой сборки.** README остаётся честным, но пользователь не знает, что
   скачивание вообще планируется, а следующий выпуск начинается с того же вопроса. Отвергнуто.
3. **Раздел-заготовка с честным `TODO` плюс инструмент, который готовит данные (выбрано).**
   В README выделено место с явным «нет», рядом — порядок действий, а числа приходят из
   сгенерированного блока `README-exe.md`, а не из рук.
4. **Публиковать exe прямо в git.** Бинарник на 40–80 МБ в истории репозитория, который клонируют
   ради исходников; история растёт на каждой сборке. Отвергнуто: для этого и нужны релизы.

## Решение

**README.** Новый раздел «Скачать готовую сборку» содержит таблицу с полями «ссылка на релиз,
файл, версия, размер, дата сборки, MD5, SHA256, VirusTotal, архив» и пометкой `TODO` в начале.
Строки заполнены словом «нет», пока файла нет; порядок заполнения описан там же четырьмя шагами.
Раздел «Как проверить скачанный exe» показывает `Get-FileHash` и `certutil` — проверка не требует
наших программ.

**Инструмент.** `tools/make_exe_report.py` считает MD5 и SHA256 потоком, пишет
`<имя>.md5`/`<имя>.sha256` в формате `md5sum`, собирает `MD5SUMS.txt` и `SHA256SUMS.txt`,
`build-info.json` и готовый блок `README-exe.md` с местом под ссылку на VirusTotal. По `--pack`
он упаковывает папку сборки в детерминированный zip: порядок файлов и дата внутри архива
фиксированы, поэтому повторная сборка того же набора даёт тот же хеш, и сумма архива не меняется
на пустом месте.

**Вызов.** `build_exe.bat` вызывает инструмент последним шагом и печатает, что делать дальше.
VirusTotal остаётся ручным шагом: загрузить файл и вставить ссылку — автоматическая загрузка в
чужой сервис без ведома владельца недопустима.

**Поправка к ADR-0046.** Правило «релиз только с вложениями» сохраняется, но требование «вложения
только из CI» снимается: файлы может собрать сопровождающий на Windows (`build_exe.bat`) и
приложить к релизу вручную. CI-сборка остаётся предпочтительной — она воспроизводима и не зависит
от машины.

Граница применимости: как только появится CI-job, собирающий exe под Windows, шаги «загрузите
вручную» из README и `.bat` убираются — остаются только данные проверки.

## Последствия

- В README появляется раздел, который сейчас честно говорит «нет», а после первой сборки — даёт
  файл, суммы и ссылку на VirusTotal; правки сводятся к вставке сгенерированного блока.
- Числа больше не набираются руками: расхождение таблицы с файлом возможно только если блок не
  обновили, и это видно по версии в блоке.
- Детерминированный zip даёт воспроизводимый хеш архива: две сборки на одной машине дают одну
  сумму, и её можно сравнивать между релизами.
- VirusTotal остаётся ручным: пока файл не загружен, строка честно помечена `TODO`.
- Затронуты: `tools/make_exe_report.py`, `tests/test_make_exe_report.py`, `build_exe.bat`,
  `README.md`, `CHANGELOG.md`, `docs/adr/0046-releases-with-assets-only.md`.
- Откат: убрать раздел из README и вызов инструмента из `.bat` — остальное (суммы, zip) не мешает
  сборке и живёт в `dist\release`.
