# ADR-0021: диагональ считается и по `RX`, и по `RY`

Статус: принято (1.6.0). Дополняет ADR-0019: там `Y`/`Z` поворачивались только на `RX`,
глубина `X` не менялась. Прежняя формула теперь — частный случай при `RY = 0`.

## Контекст

ADR-0019 закрыл вопрос с `RX`: диагональ — поворот в плоскости `Y/Z`. Но у предмета есть и
`RY`. На предмете с `RY ≠ 0` диагональный шаг оставался в плоскости `Y/Z` и не учитывал,
что ось «вверх» у него уже наклонена вперёд. Пользователь прислал формулу для сдвига при
изменённых `RX` и `RY`:

```
X_new = X + L sin(RY)
Y_new = Y − L sin(RX)
Z_new = Z + L cos(RX) cos(RY)
```

## Формула

`L = шаг/√2` — та же «половинная» длина, что и в 1.5.4 (иначе на нулевых углах прыгнул бы
эталон). Знаки берутся от клавиши: `ax = ±1` — «вперёд/назад» (он же «вверх/вниз»),
`ay = ±1` — «влево/вправо»:

```
X_new = X + ax · L · sin RY
Y_new = Y + ay · L · sin RX
Z_new = Z + ax · L · cos RX · cos RY
```

Для `Num 9` (`ax = +1`, `ay = −1`) получается ровно формула пользователя.

### Контрольный пример

```
P = (−1849.342, 416.528, 128.826),  RX = 37°,  RY = 10°,  шаг = 3.0,  Num 9
L = 3.0/√2 = 2.1213203436

ΔX = +1 · 2.1213203436 · sin 10°           = +0.368363
ΔY = −1 · 2.1213203436 · sin 37°           = −1.276642
ΔZ = +1 · 2.1213203436 · cos 37° · cos 10° = +1.668424

P' = (−1848.974, 415.251, 130.494)
```

## Свойства

* При `RY = 0` формула превращается в формулу ADR-0019 дословно: `ΔX = 0`,
  `ΔY = ay·L·sin RX`, `ΔZ = ax·L·cos RX`.
* При `RX = RY = 0` шаг идёт строго вверх/вниз на `L = шаг/√2` — как в 1.0.
* Наклон на экране в плоскости `Y/Z` — по-прежнему `90° − RX`; `RY` его не крутит.
* `RY` в плюс уводит вперёд (`ΔX > 0`), в минус — назад; знак `ΔX` задаёт `ax`, то есть
  «вверх-*» уходит вперёд, «вниз-*» — назад.
* Подъём сжимается множителем `cos RY`: при `RY = 90°` вертикальной составляющей нет.
* Длина шага: `L · √(1 + sin²RX · sin²RY)`. При одном нулевом угле ровно `L`; при больших
  углах шаг длиннее (максимум `L·√2` на `RX = RY = 90°`). Так получается потому, что формула
  пользователя — композиция двух «одиночных» поворотов, а не строгая матрица
  `Ry(RY)·Rx(RX)`: у строгой матрицы было бы `ΔX = L·sin RY·cos RX`.
* `RZ` не участвует: диагонали не крутятся вместе с поворотом вокруг вертикали.

| Клавиша (`RX = 37°`, `RY = 10°`, шаг 0.5) | `ΔX` | `ΔY` | `ΔZ` |
| --- | --- | --- | --- |
| `Num 9` вверх-вправо | +0.061 | −0.213 | +0.278 |
| `Num 7` вверх-влево | +0.061 | +0.213 | +0.278 |
| `Num 1` вниз-влево | −0.061 | +0.213 | −0.278 |
| `Num 3` вниз-вправо | −0.061 | −0.213 | −0.278 |

## Следствия, о которых надо помнить

* Диагональ пишет три поля, когда `RY ≠ 0`; `changed_fields` сам отбрасывает совпавшие
  значения, поэтому при `RY = 0` по-прежнему пишутся только `Y` и `Z`.
* Режим высоты (`Alt` + `Num 8/2`) живёт по ADR-0020 и `RX` не учитывает: его формула
  `(±sin RY, 0, ±cos RY)`. Если понадобится, чтобы и подъём учитывал `RX`
  (`ΔY = −L·sin RX`), это отдельное изменение с отдельным эталоном.
