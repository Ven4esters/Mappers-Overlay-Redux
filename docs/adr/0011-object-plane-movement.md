# ADR-0011: шаг по плоскости предмета

## Контекст

Пользователь нарисовал стрелку вдоль плоскости предмета и спросил, как добиться движения
именно в эту сторону. Прежняя формула приписывала вертикаль направлению «вперёд»:

```
ΔX, ΔY = RZ(dx · cos(RX), dy)
ΔZ     = dx · sin(RX)
```

Это неправда геометрически. Поворот `RX` — это поворот **вокруг** оси `X`: сама ось
остаётся на месте, а наклоняются перпендикулярные ей оси. Значит при `RX` поднимается
«лево-право», а «вперёд» остаётся горизонтальным. Прежняя формула давала ровно наоборот.

## Решение

Шаг считается в осях предмета и переводится в мир теми же поворотами, в каком порядке их
задаёт игра — `RX`, затем `RY`, затем `RZ`:

```
(1,0,0) → «вперёд», (0,1,0) → «влево», (0,0,1) → «вверх в осях предмета»
шаг = Rz · Ry · Rx · (dx, dy, 0) · step
```

Свойства, которые теперь проверяются тестами:

* `√(ΔX² + ΔY² + ΔZ²) = step` — длина шага сохраняется, диагональ тоже;
* вектор шага перпендикулярен нормали плоскости предмета — шаг не уводит от поверхности;
* при нулевых углах результат совпадает с прежним плоским шагом;
* при `RY = 0` порядок «Z → Y → X» и «Z → X → Y» дают одно и то же, поэтому порядок
  поворотов влияет только на предметы с креном.

Следствия для пользователя:

| Угол | Поднимается | Горизонтально |
| --- | --- | --- |
| `RX` | «влево-вправо» | «вперёд-назад» |
| `RY` | «вперёд-назад» | «влево-вправо» |
| `RZ` | ничего, доворачивает в плане | все |

## Последствия

* «Движение по `RX`» больше не отдельное направление: включается плоскость, по которой
  ходят все восемь направлений. Пользователь находит нужную клавишу по `ΔZ` в строке
  состояния.
* В режиме наклона теперь учитывается и `RY` — предупреждение «`RY` не учитывается»
  убрано.
* Знак вертикали закреплён стандартным правым поворотом: при `RX > 0` «влево» поднимается.
  Если в конкретной сборке игры знак окажется обратным, менять нужно одну строку в
  `_from_object_plane` — тесты покажут, что изменилось.
