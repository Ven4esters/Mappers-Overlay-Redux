# ADR-0045. «Прямой шаг 4/6/8/2»: формулы не влияют на прямые клавиши

- Статус: принято
- Дата: 2026-11-19
- Владелец: @Ven4esters
- Пересмотр: 2027-11-19
- Версия: 1.23.0

## Контекст

Прямые клавиши (`Num 4/6/8/2`) и раньше не использовали формулы наклона: горизонтальный шаг
считается по мировым осям `X`/`Y` с доворотом на `RZ`, а высота — по локальной оси `Z` с учётом
`RY` (`ADR-0020`). Диагонали — отдельная история с тремя формулами (`ADR-0023`, `ADR-0026`,
`ADR-0027`).

Заказчик столкнулся с тем, что на наклонённом предмете «вверх» уводит объект вбок: при `RY = 10°`
и шаге 3 м шаг равен `(0.5209, 0, 2.9544)`, то есть почти полметра в сторону. Ему нужен режим, в
котором наклон вообще не участвует в движении прямых клавиш:

> «Для ситуаций, когда RX, RY не равны нулю, формулы не должны влиять на движение Numpad 4,6,8,2.
> Они должны работать как обычно, двигая предмет влево, вправо, вперёд, назад (верх, вниз при
> включённом alt)».

Уточнения заказчика: `RZ` учитывать (это поворот предмета вокруг вертикали, «вперёд» — туда, куда
он смотрит); в режиме высоты шаг идёт строго по мировой `Z`, без наклона `RY`; переключатель —
на «Навигации», рядом с «Режимом высоты», по умолчанию выключен.

## Рассмотренные варианты

1. **Всегда двигать прямые клавиши по мировым осям.** Просто, но меняет привычное поведение у
   всех: у кого высота «вдоль предмета» — рабочая, тот потеряет её без возможности вернуть.
2. **Переключатель «Прямой шаг 4/6/8/2»** (выбран). Поведение по умолчанию не меняется, режим
   включают там, где он нужен, выбор запоминается в `config/settings.json`.
3. **Отдельные горячие клавиши «прямое движение».** Дороже: вторые привязки на четыре
   направления, конфликты с уже назначенными клавишами и обучение пользователя.
4. **«Ничего не делать».** Пользователь продолжает либо мириться со сносом по `RY`, либо
   выключать наклон предмета перед движением — то есть руками.

## Решение

`shifted(pose, direction, step, *, tilt=False, straight=False)`: при `straight=True` и наклоне
предмета (`RX` или `RY` ≠ 0) высота считается строго по мировой оси `Z` — `Δ = (0, 0, ±1)`.
Горизонтальные прямые клавиши не меняются: они и так идут по `X`/`Y` с доворотом `RZ`, а без
наклона формула высоты при `RY = 0` совпадает с прямой.

Границы применимости:

- переключатель не касается диагоналей — у них свои формулы (`ADR-0023`…`ADR-0027`);
- `RZ` продолжает поворачивать шаг: это ориентация предмета, а не наклон;
- при `RX = RY = 0` режим ничего не меняет — в этом и смысл «работать как обычно».

Флаг протаскивается через `MappingSession.step` / `capture_and_step` (поле `StepResult.straight`),
окно хранит его в `_straight`, повтор шага (`Ctrl+Y`) и удержание клавиши используют то же
значение, что и исходный шаг.

## Последствия

- Проще: наклонённый предмет можно двигать по осям мира, не выключая наклон; высота перестала
  уезжать вбок.
- Дороже: появился ещё один режим, который нужно объяснить в README и показать в подсказке над
  крестовиной; в интерфейсе — вторая строка режимов (три флажка в одну строку не помещались в
  мини-окно шириной 380).
- Затронуты: `domain/movement.py`, `application/session.py`, `config.py`,
  `ui/tabs/movement_tab.py`, `ui/window.py`, `README.md`, `CHANGELOG.md`.
- Откат: убрать флаг из `Settings` и `shifted` — поведение вернётся к `ADR-0020` без миграции
  данных: неизвестный ключ в файле настроек игнорируется.
