# ADR-0023: формулы диагоналей применяются по случаям

Статус: принято (1.7.0). Уточняет ADR-0019 и ADR-0022: их формулы не универсальны, а работают
только в своих случаях. Восстанавливает поведение из ADR-0004 для предмета без наклона.

## Контекст

К 1.6.2 диагональ считалась одной формулой при любых углах:

```
ΔX = ax · шаг · sin RY
ΔY = ay · шаг · sin RX · cos RY
ΔZ = ax · шаг · cos RX · cos RY
```

При `RX = 0` из неё остаётся `ΔZ = ax · шаг`: `Num 7/9/1/3` поднимали и опускали предмет
вместо того, чтобы двигать его вперёд-назад и влево-вправо. Заказчик указал: **каждая
присланная формула должна работать только в своём случае, а не всегда и не вместо остальных.**

## Случаи

Наклон предмета — это `RX` (по нему же интерфейс предупреждает о наклоне).

### 1. Наклона нет: `RX = 0`

Обычная диагональ в горизонтали — как задумано в ADR-0004 и как было в 1.0–1.2:

```
Δ = Rz(RZ) · (ax, ay) / √2,   ΔZ = 0
```

`Num 9` уводит вперёд-вправо (`ΔX +`, `ΔY −`), длина шага ровно `шаг`, `Z` не меняется.
`RY` в этом случае не участвует.

### 2. Наклонён только `RX`: `RX ≠ 0`, `RY = 0`

Формула 1.5.4 (ADR-0019) — поворот в плоскости `Y/Z`:

```
ΔX = 0
ΔY = ay · (шаг/√2) · sin RX
ΔZ = ax · (шаг/√2) · cos RX
```

Эталон заказчика: `RX = 37°`, шаг `2.0`, `Num 9` → `ΔY −0.851`, `ΔZ +1.129`; из точки
`(−1849.342, 416.528, 128.826)` получается `Y 415.677`, `Z 129.955`, `X` не меняется.

### 3. Наклонены `RX` и `RY`: оба не нули

Формула 1.6.2 (ADR-0022) с `L = шаг` — поворот `Rx(RX) · Ry(RY)` над локальной осью `Z`:

```
ΔX = ax · шаг · sin RY
ΔY = ay · шаг · sin RX · cos RY
ΔZ = ax · шаг · cos RX · cos RY
```

Эталоны заказчика (подтверждены в игре):

```
RX = 55°,   RY = 17°,   шаг 3 → (−1848.465, 414.178, 130.472)
RX = 41.5°, RY = 22.3°, шаг 3 → (−1848.204, 414.689, 130.895)
```

### Отдельно: режим высоты (`Alt`)

`Alt` + `Num 8/2` живёт по ADR-0020 и случаев выше не касается:
`Δ = (±шаг·sin RY, 0, ±шаг·cos RY)`.

## Почему разные множители

Множитель взят из эталона каждого случая, а не «приведён к общему виду»:

* случай 2 — `шаг/√2`: так сходится эталон `RX = 37°`, шаг `2.0` (иначе `Y` было бы `415.324`);
* случай 3 — `шаг` целиком: так сходятся оба эталона 1.6.2 (иначе `Y` было бы `414.866`).

Заказчик подтвердил обе пары чисел в игре, поэтому обе формулы сохранены дословно.

## Свойства и последствия

* `Num 7/9/1/3` без наклона больше никогда не меняют `Z` — это и был баг 1.6.2.
* Диагональ без наклона поворачивается вместе с `RZ`, как прямые клавиши; при `RX ≠ 0` — не
  поворачивается (случаи 2 и 3 считаются по осям предмета).
* Переход между случаями резкий: при `RX = 0` идёт горизонталь, при `RX = 0.001` — уже
  плоскость `Y/Z`. Это следствие «формула на случай», а не ошибка: интерфейс предупреждает о
  наклоне именно по `RX`.
* `RY` без `RX` (предмет повёрнут вокруг `Y`, но не наклонён) диагональ не меняет — как в
  1.0–1.4.
* Функции в коде: `_flat_diagonal`, `_rx_diagonal`, `_rx_ry_diagonal`, выбор в `_diagonal`.
* Тесты: `test_diagonal_without_tilt_is_horizontal`, `test_diagonal_without_tilt_goes_forward_right`,
  `test_diagonal_without_tilt_rotates_with_rz`, `test_diagonal_is_the_rotated_plane_step`,
  `test_user_example_at_37_degrees`, `test_user_example_with_rx_and_ry`,
  `test_second_user_example_with_rx_and_ry`, `test_diagonal_follows_rx_and_ry`
  (эталон по случаям), плюс проверки на уровне сессии и UI.
