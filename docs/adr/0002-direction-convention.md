# ADR-0002: направления и знаки осей

> Частично заменён [ADR-0004](0004-rotation-and-diagonal.md): диагональ теперь считается
> «шагом по прямой», а поворот `RZ` учитывается. Знаки направлений при нулевых углах
> уточнены по игре в [ADR-0007](0007-direction-signs-fixed.md): векторы в разделе
> «Решение» — исходные, действующие — в ADR-0007.

## Контекст

Пользователь задал правила для нулевых углов: вперёд — это `X` в минус, назад — `X` в
плюс, влево — `Y` в минус, вправо — `Y` в плюс, диагонали — комбинация этих правил.
Эти правила — истина для проекта, их нельзя «улучшать» по догадке.

## Решение

1. Каждое направление — единичный вектор в мире. Движение: `X += dx · шаг`,
   `Y += dy · шаг`, `Z` и углы не меняются.
   - вперёд `(-1, 0)`, назад `(1, 0)`, влево `(0, -1)`, вправо `(0, 1)`;
   - диагонали — суммы соседних: `(-1, -1)`, `(-1, 1)`, `(1, -1)`, `(1, 1)`.
2. Диагональ меняет **каждую** ось на полный шаг. По прямой предмет уезжает `шаг · √2`,
   зато значения в полях остаются ровными (`1845.000`, а не `1846.464`).
3. Результат округляется до 3 знаков (`COORD_DECIMALS`), чтобы `0.1 + 0.2` не превращалось
   в `0.30000000000000004` и не уезжало в панель.
4. Повороты в первой версии не учитываются: при `RZ ≠ 0` стрелки двигают по мировым осям,
   и UI предупреждает об этом. Правила для повёрнутых объектов будут отдельным ADR,
   когда пользователь их задаст.

## Последствия

- Тесты фиксируют таблицу из README дословно: `1850 → 1845` и т. п.
- Если понадобится «диагональ как один шаг по прямой», это одна константа режима и
  отдельный ADR, а не тихая правка формулы.
