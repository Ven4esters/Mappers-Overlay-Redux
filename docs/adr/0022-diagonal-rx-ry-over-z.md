# ADR-0022: диагональ — поворот `Rx(RX) · Ry(RY)` над локальной осью `Z`

Статус: принято (1.6.1). Дополняет ADR-0019 (там учитывался только `RX`, глубина `X` не
менялась). Версия 1.6.0 с множителем `cos RY` только у `Z` откатана: она не сохраняла длину
шага.

## Контекст

Формула пользователя для сдвига при изменённых `RX` и `RY`:

```
X_new = X + L sin θy
Y_new = Y − L sin θx cos θy
Z_new = Z + L cos θx cos θy
```

`θx = RX`, `θy = RY`, `L = шаг/√2` (та же «половинная» длина, что и в 1.5.4, иначе на нулевых
углах сдвинулся бы эталон). Сначала предполагалось, что `cos θy` есть только у `Z`; на деле
он есть у `Y` и `Z` — и тогда формула становится точным поворотом, а не приближением.

## Формула

Знаки берутся от клавиши: `ax = ±1` — «вперёд/назад» (он же «вверх/вниз»), `ay = ±1` —
«влево/вправо»:

```
X_new = X + ax · L · sin RY
Y_new = Y + ay · L · sin RX · cos RY
Z_new = Z + ax · L · cos RX · cos RY
```

Для `Num 9` (`ax = +1`, `ay = −1`) получается ровно формула пользователя.

### Почему это точный поворот

Единичный вектор «вверх» `(0, 0, ax)` поворачивается сначала вокруг `Y`, затем вокруг `X`:

```
Ry(RY) · (0, 0, ax)  = ( ax·sin RY,  0,  ax·cos RY )
Rx(RX) · предыдущее  = ( ax·sin RY, −ax·sin RX·cos RY... , ax·cos RX·cos RY )
```

то есть по модулю компоненты совпадают с формулой: `X` от `RY`, `Y` — от `RX` и `RY`,
`Z` — от обоих. Оба поворота ортогональны
([Rotation matrix](https://en.wikipedia.org/wiki/Rotation_matrix)), поэтому длина шага остаётся
`L` при любых углах.

### Контрольный пример

```
P = (−1849.342, 416.528, 128.826),  RX = 55°,  RY = 17°,  шаг = 3.0,  Num 9
L = 3.0/√2 = 2.1213203436

ΔX = +1 · 2.1213203436 · sin 17°              = +0.620214
ΔY = −1 · 2.1213203436 · sin 55° · cos 17°    = −1.661755
ΔZ = +1 · 2.1213203436 · cos 55° · cos 17°    = +1.163574

P' = (−1848.722, 414.866, 129.990)
```

## Свойства

* При `RY = 0` формула превращается в формулу ADR-0019 дословно: `ΔX = 0`,
  `ΔY = ay·L·sin RX`, `ΔZ = ax·L·cos RX`.
* При `RX = RY = 0` шаг идёт строго вверх/вниз на `L = шаг/√2`.
* Длина шага — ровно `L` при любых углах (проверено тестом `test_diagonal_length_stays_the_half_step`
  на углах до `±90°`).
* Наклон на экране в плоскости `Y/Z` — по-прежнему `90° − RX`; `RY` его не крутит.
* `RY` в плюс уводит вперёд (`ΔX > 0`), в минус — назад; знак `ΔX` задаёт `ax`: «вверх-*»
  уходит вперёд, «вниз-*» — назад.
* `RY` сжимает `Y` и `Z` множителем `cos RY`: при `RY = 90°` шаг идёт строго вперёд.
* `RZ` не участвует: диагонали не крутятся вместе с поворотом вокруг вертикали.

| Клавиша (`RX = 55°`, `RY = 17°`, шаг 0.5) | `ΔX` | `ΔY` | `ΔZ` |
| --- | --- | --- | --- |
| `Num 9` вверх-вправо | +0.103 | −0.277 | +0.194 |
| `Num 7` вверх-влево | +0.103 | +0.277 | +0.194 |
| `Num 1` вниз-влево | −0.103 | +0.277 | −0.194 |
| `Num 3` вниз-вправо | −0.103 | −0.277 | −0.194 |

## Следствия, о которых надо помнить

* Диагональ пишет три поля, когда `RY ≠ 0`; `changed_fields` сам отбрасывает совпавшие
  значения, поэтому при `RY = 0` по-прежнему пишутся только `Y` и `Z`.
* Режим высоты (`Alt` + `Num 8/2`) живёт по ADR-0020 и `RX` не учитывает: его формула
  `(±sin RY, 0, ±cos RY)`. Если понадобится, чтобы и подъём учитывал `RX`
  (`ΔY = −L·sin RX`), это отдельное изменение с отдельным эталоном.
* Тесты: `test_user_example_with_rx_and_ry`, `test_diagonal_follows_rx_and_ry`,
  `test_diagonal_length_stays_the_half_step`, `test_diagonal_components_shrink_with_ry`,
  `test_diagonal_at_zero_ry_keeps_the_old_formula`, плюс проверки на уровне сессии и UI.
