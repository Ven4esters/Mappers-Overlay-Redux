# ADR-0022: диагональ — поворот `Rx(RX) · Ry(RY)` над локальной осью `Z`

Статус: принято (1.6.1), исправлено в 1.6.2 (см. «Поправка» в конце: `L` — полный шаг, а не
`шаг/√2`). Дополняет ADR-0019 (там учитывался только `RX`, глубина `X` не менялась). Версия
1.6.0 с множителем `cos RY` только у `Z` откатана: она не сохраняла длину шага.

> **Кратко о поправке 1.6.2.** Все формулы ниже читаются с `L = шаг` (полный шаг). Множитель
> `1/√2` был моей ошибкой: он остался от прежней «плоскостной» схемы, где каждая ось получала
> половину шага. Контрольный пример 1.6.2: `RX = 55°`, `RY = 17°`, шаг `3.0`, `Num 9` →
> `(−1848.465, 414.178, 130.472)`.

## Контекст

Формула пользователя для сдвига при изменённых `RX` и `RY`:

```
X_new = X + L sin θy
Y_new = Y − L sin θx cos θy
Z_new = Z + L cos θx cos θy
```

`θx = RX`, `θy = RY`, `L = шаг`. Сначала предполагалось, что `cos θy` есть только у `Z`; на
деле он есть у `Y` и `Z` — и тогда формула становится точным поворотом, а не приближением.

## Формула

Знаки берутся от клавиши: `ax = ±1` — «вперёд/назад» (он же «вверх/вниз»), `ay = ±1` —
«влево/вправо»:

```
X_new = X + ax · L · sin RY
Y_new = Y + ay · L · sin RX · cos RY
Z_new = Z + ax · L · cos RX · cos RY
```

Для `Num 9` (`ax = +1`, `ay = −1`) получается ровно формула пользователя.

### Почему это точный поворот

Единичный вектор «вверх» `(0, 0, ax)` поворачивается сначала вокруг `Y`, затем вокруг `X`:

```
Ry(RY) · (0, 0, ax)  = ( ax·sin RY,  0,  ax·cos RY )
Rx(RX) · предыдущее  = ( ax·sin RY, −ax·sin RX·cos RY... , ax·cos RX·cos RY )
```

то есть по модулю компоненты совпадают с формулой: `X` от `RY`, `Y` — от `RX` и `RY`,
`Z` — от обоих. Оба поворота ортогональны
([Rotation matrix](https://en.wikipedia.org/wiki/Rotation_matrix)), поэтому длина шага остаётся
`L` при любых углах.

### Контрольный пример

```
P = (−1849.342, 416.528, 128.826),  RX = 55°,  RY = 17°,  шаг = 3.0,  Num 9
L = 3.0

ΔX = +1 · 3.0 · sin 17°              = +0.877115
ΔY = −1 · 3.0 · sin 55° · cos 17°    = −2.350077
ΔZ = +1 · 3.0 · cos 55° · cos 17°    = +1.645542

P' = (−1848.465, 414.178, 130.472)
```

Второй эталон, подтверждённый в игре:

```
P = (−1849.342, 416.528, 128.816),  RX = 41.5°,  RY = 22.3°,  шаг = 3.0,  Num 9

ΔX = +3.0 · sin 22.3°              = +1.138368
ΔY = −3.0 · sin 41.5° · cos 22.3°  = −1.839188
ΔZ = +3.0 · cos 41.5° · cos 22.3°  = +2.078823

P' = (−1848.204, 414.689, 130.895),  |Δ| = 3.000
```

## Свойства

* При `RY = 0` формула превращается в формулу ADR-0019 дословно: `ΔX = 0`,
  `ΔY = ay·L·sin RX`, `ΔZ = ax·L·cos RX`.
* При `RX = RY = 0` шаг идёт строго вверх/вниз на `L = шаг`.
* Длина шага — ровно `L = шаг` при любых углах (тест
  `test_diagonal_length_is_the_full_step_with_both_angles` на углах до `±90°`).
* Наклон на экране в плоскости `Y/Z` — по-прежнему `90° − RX`; `RY` его не крутит.
* `RY` в плюс уводит вперёд (`ΔX > 0`), в минус — назад; знак `ΔX` задаёт `ax`: «вверх-*»
  уходит вперёд, «вниз-*» — назад.
* `RY` сжимает `Y` и `Z` множителем `cos RY`: при `RY = 90°` шаг идёт строго вперёд.
* `RZ` не участвует: диагонали не крутятся вместе с поворотом вокруг вертикали.

| Клавиша (`RX = 55°`, `RY = 17°`, шаг 0.5) | `ΔX` | `ΔY` | `ΔZ` |
| --- | --- | --- | --- |
| `Num 9` вверх-вправо | +0.146 | −0.392 | +0.274 |
| `Num 7` вверх-влево | +0.146 | +0.392 | +0.274 |
| `Num 1` вниз-влево | −0.146 | +0.392 | −0.274 |
| `Num 3` вниз-вправо | −0.146 | −0.392 | −0.274 |

## Следствия, о которых надо помнить

* Диагональ пишет три поля, когда `RY ≠ 0`; `changed_fields` сам отбрасывает совпавшие
  значения, поэтому при `RY = 0` по-прежнему пишутся только `Y` и `Z`.
* Режим высоты (`Alt` + `Num 8/2`) живёт по ADR-0020 и `RX` не учитывает: его формула
  `(±sin RY, 0, ±cos RY)`. Если понадобится, чтобы и подъём учитывал `RX`
  (`ΔY = −L·sin RX`), это отдельное изменение с отдельным эталоном.
* Тесты: `test_user_example_with_rx_and_ry`, `test_second_user_example_with_rx_and_ry`,
  `test_diagonal_follows_rx_and_ry`,
  `test_diagonal_length_is_the_full_step_with_both_angles`,
  `test_diagonal_components_shrink_with_ry`, `test_diagonal_at_zero_ry_keeps_the_old_formula`,
  плюс проверки на уровне сессии и UI.

## Поправка 1.6.2 — `L` это полный шаг

В 1.6.1 стояло `L = шаг/√2`: множитель остался от «плоскостной» схемы 1.5.4, где диагональ
делила шаг между осями. Заказчик дал эталон, из которого видно, что это неверно:

```
P = (−1849.342, 416.528, 128.826), RX = 55°, RY = 17°, шаг 3.0, Num 9
ожидание: (−1848.465, 414.178, 130.472)
1.6.1 давал: (−1848.722, 414.866, 129.990)
```

С `L = шаг` формула — это поворот единичного вектора `(0, 0, ax)`: длина сдвига ровно `шаг`,
и это же сходится с эталоном. Тем самым перестал действовать эталон 1.5.4 «шаг 2, `RX = 37°`
→ `Y 415.677`, `Z 129.955`»: с полным шагом это `Y 415.324`, `Z 130.423`. Значения в тестах и
README пересчитаны.
