# ADR-0013: шаг в плоскости экрана

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

> **Заменён ADR-0015 (1.5.0).** Режим по `Alt` теперь просто поднимает и опускает предмет
> (`Num 8` — вверх, `Num 2` — вниз). Этот документ оставлен как история решения.

## Контекст

ADR-0011 перевёл шаг в плоскость предмета: при `RX = 45°` «влево-вправо» поднимается,
«вперёд-назад» остаётся горизонтальным. Геометрически это верно, но пользователю не
подошло. На скриншоте он отметил направления, куда предмет должен уходить по его
ощущению от экрана:

* `Num 4` — вверх-влево (это старая модель давала, и это устраивало);
* `Num 6` — вниз-вправо (тоже устраивало);
* `Num 8` — вверх-вправо, `Num 2` — вниз-влево (а старая модель уводила их в глубину
  по `X`).

Дополнение к ADR-0011 доказывает, что «вверх-вправо» в плоскости наклонённого предмета
недостижимо: при наклоне `RX` компоненты `ΔY` и `ΔZ` всегда одного знака, значит подъём
всегда сопровождается одной и той же стороной. Пользователь подтвердил, что готов на
уход с плоскости — ему нужны углы монитора, а не скат.

## Решение

Режим по `Alt` считает шаг в **плоскости экрана**. Камера смотрит вдоль `X`, поэтому
на экране: вправо — `−Y`, вверх — `+Z`. Клавиши задают диагонали экрана, то есть карта
повёрнута на 45° относительно осей `Y`/`Z`:

```
ΔY = (−dx + dy) / √2 · step
ΔZ = ( dx + dy) / √2 · step
ΔX = 0
```

| Клавиша | `(dx, dy)` | `ΔY` | `ΔZ` | Экран |
| --- | --- | --- | --- | --- |
| `Num 8` | `(1, 0)` | −0.707 | +0.707 | вверх-вправо |
| `Num 2` | `(−1, 0)` | +0.707 | −0.707 | вниз-влево |
| `Num 4` | `(0, 1)` | +0.707 | +0.707 | вверх-влево |
| `Num 6` | `(0, −1)` | −0.707 | −0.707 | вниз-вправо |
| `Num 7` | `(1, 1)` | 0 | +1 | вверх |
| `Num 9` | `(1, −1)` | −1 | 0 | вправо |
| `Num 1` | `(−1, 1)` | +1 | 0 | влево |
| `Num 3` | `(−1, −1)` | 0 | −1 | вниз |

Свойства, закреплённые тестами:

* длина шага сохраняется: `ΔY² + ΔZ² = step²` для всех восьми направлений;
* `ΔX = 0` — в глубину шаг не уходит;
* результат не зависит от `RX`, `RY`, `RZ` — углы на экранные оси не влияют;
* диагонали клавиш дают ровно шаг по одной оси, без «половинок».

## Следствия и ограничения

* Предмет сходит с наклонной плоскости: это плата за направления, которые видит
  пользователь. Для езды по скату режим не годится, для «поднять и подвинуть» — годится.
* Соответствие «вправо = `−Y`» верно для камеры, смотрящей вдоль `X` (как в LSP-маппере на
  скриншотах). При развороте камеры соответствие изменится; настраиваемого поворота
  экранных осей пока нет — это следующий шаг, если понадобится.
* ADR-0011 остаётся в силе как описание плоскости предмета и как объяснение, почему
  «вверх-вправо» в ней недостижимо.
