# ADR-0017: диагональ — локальный шаг, повёрнутый на `RX`

- Владелец: @Ven4esters
- Пересмотр: 2027-11-19

Статус: **заменено в 1.5.3 (ADR-0018).** Здесь локальная диагональ бралась в плоскости
`Y/Z` (`(0, ay, ax)/√2`); контрольный пример пользователя показал, что диагональ живёт в
плоскости `X/Z`, иначе `Y`/`Z` уходят от расчёта и клавиши «вверх-вправо»/«вверх-влево»
неразличимы.

## Контекст

Две попытки описать диагональ числами из угла провалились:

1. ADR-0014 — фиксированные 45° (`ΔY = dy·шаг`, `ΔZ = dx·шаг`). На предмете с `RX = 45°`
   совпадало с поверхностью, при `RX = 37°` — нет.
2. ADR-0016 — компоненты из угла (`ΔY = ay·cos RX`, `ΔZ = ax·sin RX`). На бумаге это
   «наклон = `tan RX`», но на 37° предмет всё равно съезжал: шаг шёл под 37° по экрану,
   хотя предмет повёрнут в своей плоскости.

Пользователь сформулировал правило сам:

> `P_new = P + Rx(37°) · Δ_local`, где `Δ_local` — нужное смещение в локальных осях объекта.

Это и есть недостающая часть: смещение задаётся **в осях предмета** и лишь затем
поворачивается в мир. Подбирать коэффициенты под угол больше не нужно — угол входит в
матрицу, а не в формулу компонент.

## Решение

Локальные оси предмета: `X` — вперёд, `Y` — влево, `Z` — вверх. Диагональ в них — обычный
вектор `(0, ±1, ±1)`, нормированный к единице:

```
Δ_local = (0, ay, ax) / √2      (ax, ay — экранные оси клавиши)
```

Дальше — поворот матрицей `Rx(RX)`:

```
Rx(RX) = | 1      0         0    |
         | 0   cos RX   −sin RX  |
         | 0   sin RX    cos RX  |

ΔX = 0
ΔY = ay·cos RX − ax·sin RX
ΔZ = ay·sin RX + ax·cos RX
```

| Клавиша | `(ax, ay)` | `RX = 0°` | `RX = 37°` | `RX = 45°` |
| --- | --- | --- | --- | --- |
| `Num 9` вверх-вправо | `(1, −1)` | `Y −0.354, Z +0.354` | `Y −0.495, Z +0.070` | `Y −0.500, Z 0` |
| `Num 7` вверх-влево | `(1, 1)` | `Y +0.354, Z +0.354` | `Y +0.070, Z +0.495` | `Y 0, Z +0.500` |
| `Num 1` вниз-влево | `(−1, 1)` | `Y +0.354, Z −0.354` | `Y +0.495, Z −0.070` | `Y +0.500, Z 0` |
| `Num 3` вниз-вправо | `(−1, −1)` | `Y −0.354, Z −0.354` | `Y −0.070, Z −0.495` | `Y 0, Z −0.500` |

(шаг 0.5 м; при `RX = 0` числа совпадают с прежними)

## Почему так

* **Смещение инвариантно.** В осях предмета шаг всегда один и тот же: `(0, ±1, ±1)/√2`.
  Поэтому копии, поставленные подряд, не расходятся между собой ни при каком угле — «линия
  к линии». Это проверяется обратным поворотом на `−RX`:
  `test_diagonal_keeps_its_local_direction_at_any_angle`.
* **Длина шага сохраняется** при любом угле: поворот не растягивает вектор. `|Δ| = шаг`.
* **Углы между клавишами сохраняются.** Соседние диагонали (`Num 9` и `Num 7`) остаются
  перпендикулярными, противоположные (`Num 9` и `Num 1`) — противоположными.
* **`RX = 0` — прежнее поведение** (0.354 на 0.354 при шаге 0.5 м): менять привычку не нужно.
* **`ΔX = 0`.** Поворот вокруг `X` не даёт компоненты по `X`, глубина остаётся за прямыми
  клавишами.
* `RZ` по-прежнему не участвует (ADR-0014): диагонали не крутятся вместе с поворотом вокруг
  вертикали. Это осознанное сохранение прежней привычки.

## Следствия

* На 37° «вверх-вправо» на экране выглядит как движение почти по горизонтали (≈8°):
  предмет повёрнут на 37° по часовой, и его собственная диагональ наклонена на 45° − 37°.
  Это не ошибка — это и есть движение по диагонали предмета.
* При `RX = 45°` «вверх-вправо» идёт строго по `−Y`, «вверх-влево» — строго по `+Z`.
* Угол берётся из панели на каждом шаге, поэтому ручное изменение `RX` сразу меняет
  направление диагоналей.
