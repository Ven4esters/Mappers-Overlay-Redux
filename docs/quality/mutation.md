# Мутационное тестирование формул сдвига

Эталонные тесты (`tests/test_movement.py`) сверяют числа, но не отвечают на вопрос
«а поймает ли тест ошибку, если формулу сломать». Мутация отвечает: инструмент `mutmut`
по одной подменяет операторы и литералы в `map_overlay/domain/movement.py`, гоняет
`tests/test_movement.py` + `tests/test_properties.py` и считает, сколько подмен тесты
не заметили.

Запуск (из `.venv`, чтобы `python` в конфиге был тем же, что у тестов):

```bash
PATH="$PWD/.venv/bin:$PATH" python -m mutmut run
PATH="$PWD/.venv/bin:$PATH" python -m mutmut results
```

Конфигурация — `setup.cfg`, раздел `[mutmut]`: мутируется только `movement.py`, тесты —
только по нему, поэтому прогон занимает минуты, а не часы. В CI это недельный
неблокирующий job `.github/workflows/mutation.yml` (см. пункт 18 плана): мутация — не
гейт на PR, её медленность не должна задерживать правки.

## Результат 1.26.0

| Показатель | Значение |
| --- | --- |
| Мутантов в `domain/movement.py` | 138 |
| Убито | 120 |
| Выжило | 18 |
| Доля выживших | **13.0 %** (цель ≤ 15 %) |

Все 18 выживших — **эквивалентные**: таких значений в области определения быть не
может, либо итог всё равно округляется. Настоящих дыр в тестах по этому файлу нет.

## Почему каждый выживший эквивалентен

| Мутант | Что подменено | Почему неотличим |
| --- | --- | --- |
| `world_dz = None` | `0.0` → `None` в прямом шаге | ниже стоит `if world_dz:`; `None` и `0.0` одинаково ложны, `Z` не трогается |
| `round(..., 12)` → `round(..., 13)` (9 мутантов) | точность промежуточного округления | результат домножается на шаг и округляется до `COORD_DECIMALS = 3`; 12-й и 13-й знак не переживают это округление |
| `ax * ay > 0` → `ax / ay > 0` (2 мутанта) | форма проверки знака пары | `Direction.axes` — это `(±1, ±1)`: произведение и частное положительны ровно в одном и том же случае |
| `ax * ay > 0` → `>= 0`, `ax * ay < 0` → `<= 0`, `< 1` (3 мутанта) | границы сравнения | произведение не бывает нулём: у диагонали обе оси ±1 |
| `dx / length` → `dx * length` (2 мутанта) | нормировка в `_normalize` | у всех направлений `hypot(dx, dy) = 1`, деление и умножение на единицу совпадают |
| `degrees == 0.0` → `== 1.0` | условие быстрого возврата в `_rotate` | при `0°` поворот и так единичный (`cos 0 = 1`, `sin 0 = 0`), а `1°` считается той же формулой |

## Что было найдено и закрыто

Первый прогон дал 40 выживших (28.8 %). Реальные дыры, а не эквиваленты:

* **Подписи и подсказки.** `DIAGONAL_TITLES`, `ALT_TITLES`, `alt_hint()` — текст, который
  видит пользователь в tooltip'ах, не проверялся никем: подмену строки тесты не замечали.
* **Выбор читаемых углов.** `first_angle_fields` и `next_angle_fields` проверялись только
  «на глаз» через `changed_fields`; замена `и` на `или` и наоборот не ловилась. Теперь
  есть таблица на все сочетания `tilt`/`straight`.
* **Текст ошибки шага.** Проверялся через `pytest.raises(..., match=...)`, а `match` — это
  поиск подстроки: обёртка `XX…XX` вокруг сообщения совпадала. Заменено на сравнение
  строки целиком.
* **Граница допуска в `changed_fields`.** `<` и `<=` не различались: разницу ровно в
  допуск никто не проверял.

## Как читать отчёт следующего прогона

Строка `Survived` в `mutmut results` перечисляет номера мутантов; `mutmut show <номер>`
показывает диф. Если выжил мутант, которого нет в таблице эквивалентов выше, — это дыра в
тестах: сначала проверка, потом правка, и только потом добавление мутанта в таблицу.
