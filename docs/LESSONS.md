# Памятка: ошибки и их решения

Живой документ. **Читать перед любой правкой движения, осей и записи координат** и
дописывать сюда каждый повторяющийся промах — чтобы не проходить один и тот же круг заново.

## Эталон: «первая версия» — это первый релиз 2.0

| Что | Как понимать |
| --- | --- |
| **Первая версия** | Коммит `d2db3d0` — «feat!: LSP Mapper Overlay 2.0 — приложение переписано с нуля». Всё, что было до него (старая `mapper_assist`, коммиты `4c524c3` и раньше), **не считается**: хранилище обнуляли. |
| Как проверить | `git show d2db3d0:lsp_overlay/domain/movement.py` |
| Что там было | Один режим — по осям предмета: `R = Rz·Ry·Rx`, наклоны `RX`/`RY` **учитываются** (`use_tilt = True`), `Z` меняется только диагональю по плоскости детали. |
| Чем это закреплено | `tests/first_release_steps.json` (720 эталонных шагов, сняты прогоном `move()` из `d2db3d0`) + `tests/test_first_release_parity.py`. Любое расхождение — регресс. |

Если поведение движения расходится с этим эталоном — прав не пользователь, а этот файл.
Если кажется, что виновата математика, сначала прогоните
`pytest tests/test_first_release_parity.py` — она сверяет 720 комбинаций.

## Правила, которые уже спасли бы время

1. **Не менять умолчания без теста на умолчания.** Оси движения переделывались четыре раза
   (2.9.0 «мир», 2.10.0 поправка камеры, 2.11.0 «предмет», 2.12.0 «только RZ»), потому что
   менялось умолчание, а теста «умолчание = первая версия» не было. Теперь есть:
   `Settings().move_frame is MoveSpace.OBJECT` и `Settings().use_tilt is True`.
2. **Сначала сверка, потом гипотеза.** Если пользователь говорит «сдвиг не туда», порядок
   действий: (а) прогнать эталон, (б) посмотреть, что реально уходит в панель
   (`_move_report`, `pending_fields`), (в) только потом трогать формулу. Фраза «ошибка в
   расчёте шага» уже трижды была тупиком: расчёт совпадал, расходились оси/камера/наклоны.
3. **Одна координата ≠ одна кнопка.** В осях предмета при `RZ = 70°` «влево» обязано менять
   `X` и `Y` одновременно (`ΔX −0.342 · ΔY −0.940` на метр) — это норма, а не диагональ.
   Диагональ — это когда направление не совпадает с осью детали.
4. **Наклоны `RX`/`RY` — часть первой версии.** Выключать их «для простоты» нельзя: на
   наклонённой детали шаг поедет иначе, чем в первой версии. Выключаются только галочкой.
5. **Режимы — добавка, не умолчание.** «Мир», «Якорь», поправка на камеру и поправки
   направлений живут рядом, но по умолчанию работает режим первой версии.

## Ошибки среды и тестов

| Симптом | Причина и лечение |
| --- | --- |
| `ImportError: libGL.so.1` | Нет Qt-библиотек: `bash /tmp/make_stubs.sh .venv` и запуск с `LD_PRELOAD=/tmp/glstub/libglstub.so LD_LIBRARY_PATH=/tmp/glstub`, для окна — `QT_QPA_PLATFORM=offscreen`. |
| `malloc_consolidate(): unaligned fastbin chunk` | Шум стабов Qt, а не ошибка приложения. Тесты при этом проходят. |
| `Pose(...)` с частью полей | Молча даёт нули: все `x/y/z/rx/ry/rz` задавать явно. |
| `QComboBox.currentIndexChanged` срабатывает раньше словарей | Подключать сигнал только после наполнения списка и подписей. |
| `place_join(refresh=True)` подменял базу стыка | Перечитывание панели перед стыком выключено (`refresh=False`). |
| Тест статуса читает готовый текст после `action_apply` | Читать `lbl_status` **до** применения, иначе текст уже заменён. |
| Четыре старых теста ждали оси предмета | Они помечены явным `frame=MoveSpace.OBJECT`; не возвращать им другие оси. |
| `ruff` ругается на длинные строки/порядок импортов | `ruff format` + `ruff check --fix`. |

## Выпуск версии: чек-лист

1. `ruff format --check .`, `ruff check .`, `mypy lsp_overlay`, `pytest --cov` (≥ 80 %).
2. `pytest tests/test_first_release_parity.py` — эталон первой версии.
3. Собрать zip, распаковать в чистую папку, прогнать тесты и `main.py --debug`,
   проверить `logs/session_ready.txt` = `<версия> <python>`.
4. Обновить `CHANGELOG.md`, `README.md`, ADR и этот файл; версию — в `pyproject.toml` и
   `lsp_overlay/__init__.py`.
