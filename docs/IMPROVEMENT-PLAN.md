# План улучшений Mapper's Overlay Redux

Снимок на 2026-11-19, версия 1.23.1. Здесь — что измерено, что из этого следует и в каком порядке
браться. План живой: пункты закрываются версиями, а не «когда-нибудь».

## Как собирались данные

| Что | Чем |
| --- | --- |
| Размер и структура кода | подсчёт строк по слоям, `ast` по `ui/window.py` |
| Покрытие | `pytest --cov=map_overlay --cov-branch --cov-report=term-missing` |
| Сложность и сопровождаемость | `radon cc`, `radon mi` |
| Стоимость шага | `CalibratedPanel` с фейковыми вводом, буфером и часами: считаются паузы и операции |
| Раскладка и DPI | окно поднимается на offscreen-платформе, сравниваются `sizeHint` и видимая область |
| Зависимости | `pip list --outdated` против PyPI |
| CI | `gh api .../actions/runs/<id>/jobs` — длительности job'ов |

## Снимок состояния

- **Код:** 9018 строк в `map_overlay` (47 файлов), 1436 в `tools`, 7923 в тестах. Слои: `ui` 48 %,
  `domain` 18 %, корень 13 %, `application` 10 %, `infrastructure` 10 %.
- **Тесты:** 1258 штук, 12–15 с; покрытие 92 % по ветвям. Слабые места: `infrastructure/win32_input.py` 48 %,
  `infrastructure/hotkeys.py` 73 %, `main.py` 79 %, `paths.py` 80 %, `ui/tasks.py` 85 %,
  `ui/window.py` 88 % (94 непокрытые строки из 912).
- **Сложность:** максимум `WindowsHotkeySource._decide` — 19, `NameSearch.match` — 18,
  `lemmas._build_book` — 17, `_alias_groups` — 14. Индекс сопровождаемости `ui/window.py` — 0.00
  (худшая оценка): 1423 строки, 88 методов в одном классе.
- **Шаг предмета:** 0.51 с пауз на прямой шаг (9 операций ввода, 5 обращений к буферу), 0.86 с на
  диагональ, 1.31 с в режиме «Всегда считать позицию», 1.66 с на диагональ в нём же.
  Слагаемые: сверка поля `X` — 0.16 с, запись поля с проверкой — 0.35 с, чтение поля — 0.16 с.
- **Экран:** при масштабе 200 % вкладке нужно 728 px, видно 703 px — 25 px уходит за край; в
  мини-версии нужно 380 px, видно 337 px — 43 px. То есть на ноутбуках с масштабом строка режимов
  обрезается, и это видно на скриншотах README.
- **Зависимости:** `PySide6-Essentials` 6.8.1 при актуальной 6.12.0, `pyperclip` 1.9.0 → 1.11.0,
  `mypy` 1.11.2 → 2.4.1, `pytest` 9.0.3 → 9.2.0, `pyinstaller` 6.10.0 → 6.22.3, `bandit`,
  `build`, `pip-audit` тоже отстали. Пины точные, lock-файла нет, `requirements.txt` дублирует
  `pyproject.toml`.
- **CI:** пять job'ов, весь прогон ~51 с, каждый job заново ставит PySide6. Нет job'а под Windows,
  нет запуска по расписанию, нет автопубликации релиза, нет обновления зависимостей.
- **Процесс:** ветка `main` содержит только исходный `Initial commit` — продукта в основной ветке
  нет, поэтому бейдж CI показывает «no status», а GitHub Releases не создавались ни разу.

## Что улучшить

Приоритет — по ущербу, а не по красоте: сначала то, что ломает доверие к прогонам и портит данные
пользователя, потом скорость, потом устройство кода.

> **Поправка от 1.23.4.** GitHub Releases в проекте не публикуются, пока вложения не собирает CI
> (`ADR-0046`): релиз без файлов не даёт пользователю ничего сверх тега, а описание дублирует
> CHANGELOG. Поэтому пункты 1 и 20 выполняются вместе — сначала job по тегу, который собирает архив,
> SBOM и `SHA256SUMS`, потом сам релиз. Опубликованные было релизы 1.23.2 и 1.23.3 удалены, теги
> остались.

### P0. Риски, которые видны снаружи

**1. `main` не содержит продукта.** Репозиторий выглядит заброшенным: в основной ветке один
файл-заглушка, все версии живут в рабочих ветках, GitHub Releases пусты.
_Сделать:_ merge-реквест в `main`, защита ветки с обязательными проверками «Стиль и типы», «Тесты»,
«Безопасность», «Документация», «Сборка и SBOM»; релиз на каждый тег с вложением
`Mappers_Overlay_Redux_vX.Y.Z.zip` и `sbom.json` — но только вместе с CI-сборкой вложений
(`ADR-0046`), а не описанием без файлов.
_Проверка:_ бейдж CI зелёный на `main`, в Releases лежит архив последней версии.
_Оценка:_ S. _Риск:_ низкий.

**2. Оверлей затирает буфер обмена.** `CalibratedPanel.read_field` кладёт в буфер пустую строку
перед каждым чтением, а после записи там остаётся координата. Скопированный текст пользователя
пропадает на каждом шаге.
_Сделать:_ сохранить содержимое буфера перед обменом и вернуть после (в `finally`), в том числе при
отмене и ошибке; в журнал — только признак «буфер восстановлен», без содержимого.
_Проверка:_ тест: буфер до/после шага совпадает; при `ClipboardError` тоже.
_Оценка:_ S. _Риск:_ низкий.
_Статус:_ ✅ выполнено в 1.24.0 — буфер возвращается в `finally`, есть тесты на успех,
отмену и ошибку.

**3. Два экземпляра оверлея ставят два хука.** Запустили дважды — каждая клавиша приходит дважды,
шаги удваиваются, а причина не видна.
_Сделать:_ именованный мьютекс (или `QSharedMemory`): второй экземпляр показывает сообщение,
поднимает окно первого и выходит с кодом 2.
_Проверка:_ тест на «замок занят → второй экземпляр не стартует»; в `--check-only` — строка о
занятости.
_Оценка:_ S. _Риск:_ низкий.
_Статус:_ ✅ выполнено в 1.24.0 — `InstanceLock` (ADR-0048), второй запуск выходит с кодом 2,
`--check-only` показывает замок.

**4. Windows не проверяется в CI.** Продукт работает только под Windows, а `win32_input.py`
покрыт на 48 % и ни разу не запускался в CI: ошибки в `ctypes`-вызовах ловятся только в игре.
_Сделать:_ job `windows-latest`: `pytest` (offscreen), `build_exe.bat` на `--check-only`,
проверка, что `dist` содержит словарь лемм и иконку; артефакт сборки.
_Проверка:_ job зелёный, покрытие `win32_input` ≥ 80 %.
_Оценка:_ M. _Риск:_ средний (PyInstaller на раннере медленный).
_Статус:_ ✅ выполнено в 1.24.1 — шестая проверка «Windows» на `windows-latest`: тесты
(offscreen), `--check-only`, иконка, сборка exe через PyInstaller, проверка комплекта (exe,
`lemmas.json`, `qwindows.dll`) и артефакт `windows-build`.
Джоба сразу нашла три настоящих дефекта, невидимых на Linux: прогон падал на завершении (код 139),
окно обрезало вкладку на крупном системном шрифте, а русский вывод (`--check-only`,
`tools.make_icons`) падал на кодировке консоли cp1252. Все три исправлены; на второй случай есть тест со шрифтом 12 пунктов, на третий — запуск
с `PYTHONIOENCODING=cp1252`: оба воспроизводят Windows на эталонном Linux.

**5. Зависимости заморожены на 2024 году.** Точные пины без lock-файла: обновление — ручная правка
четырёх файлов, а патчи безопасности Qt не приезжают вовсе.
_Сделать:_ диапазоны для рантайма (`PySide6-Essentials>=6.8,<7`, `pyperclip>=1.9,<2`), lock-файл
(`uv lock`), `dependabot` на еженедельное обновление, отдельный job `pip-audit` по расписанию.
_Проверка:_ lock воспроизводит окружение; dependabot открывает PR; еженедельный аудит зелёный.
_Оценка:_ M. _Риск:_ средний (обновление Qt требует прогона тестов UI).
_Статус:_ ✅ выполнено в 1.24.1 — диапазоны `PySide6-Essentials>=6.8,<6.12` и
`pyperclip>=1.9,<2`, `requirements.lock` (`uv pip compile`), Dependabot раз в неделю и
`pip-audit` по расписанию; решение и причина верхней границы — в `ADR-0049`.

**6. Отмена работает только с фокусом у окна.** `Ctrl+Z` слушает окно, а клавиатура обычно у игры:
в бою отменить шаг нельзя, надо кликать по оверлею.
_Сделать:_ перехватывать `Ctrl+Z`/`Ctrl+Y` тем же хуком, что и Numpad (новые действия `UNDO`/`REDO`
с привязками по умолчанию), окно — запасной путь. Решение — в ADR.
_Проверка:_ тест: нажатие при фокусе у чужого окна отменяет шаг; `Ctrl+Z` в поле ввода по-прежнему
правит текст.
_Оценка:_ M. _Риск:_ средний (конфликт с игрой — предупреждение, как у остальных клавиш).
_Статус:_ ✅ выполнено в 1.24.2 — действия `UNDO`/`REDO` с привязками `Ctrl+Z`/`Ctrl+Y` (`ADR-0050`),
клавиша забирается только с зажатым `Ctrl` и только когда окно оверлея не активно; в окне сочетание
обрабатывает Qt, поэтому в полях ввода `Ctrl+Z` правит текст. Модификаторы больше не попадают в
привязку при записи.

### P1. Скорость и экран

**7. Не сверять панель после своей же записи.** Каждый шаг начинается с чтения `X` (0.16 с) даже
сразу после того, как оверлей сам записал это поле.
_Сделать:_ «токен самозаписи»: если последняя запись была меньше N секунд назад и предмет тот же,
сверку пропустить, оставив её на первый шаг после «Считать» и после паузы.
_Проверка:_ паузы прямого шага 0.51 → 0.35 с; тест на «чужое изменение после паузы всё равно
ловится».
_Оценка:_ S. _Риск:_ средний (ослабевает защита от чужих правок — нужен ADR и настройка).
_Статус:_ ✅ выполнено в 1.25.0 — токен самозаписи (`ADR-0051`): после своей записи сверка `X`
пропускается `self_write_grace` секунд (по умолчанию 2, настраивается, `0` — сверять всегда), а
после паузы или расхождения позы возвращается. Пауза шага подряд — 0.35 с; тесты: «своя запись не
перечитывает `X`», «после паузы чужое изменение ловится», «внутри паузы расхождение ловится».

**8. Читать только нужные поля.** В режиме «Всегда считать позицию» читаются все шесть полей, хотя
для прямого шага нужны `X` и `RZ`, для диагонали — ещё `RX`/`RY`, а `Y`/`Z` только те, что меняются.
_Сделать:_ таблица «направление → нужные поля» в `domain`, чтение по ней.
_Проверка:_ «Всегда считать» на прямой шаг 1.31 → ~0.8 с, диагональ 1.66 → ~1.1 с; тесты эталонов
не меняются.
_Оценка:_ M. _Риск:_ средний (недочитанное поле — неверная формула; закрывается тестами по
направлениям и углам).
_Статус:_ ✅ выполнено в 1.25.0 — `first_angle_fields`/`next_angle_fields` в `domain/movement.py`,
выборочное чтение в `MappingSession._read_before_step`: сначала углы (прямой шаг — `RZ`, высота —
`RY`, диагональ — `RX`, потом `RY`/`RZ`), затем только те координаты, которые шаг меняет. Тесты
сравнивают результат с полным чтением на всех направлениях и режимах.

**9. Запись нескольких полей одним кликом.** Диагональ пишет `X`, `Y`, `Z` тремя кликами; в
стандартной форме панели между полями работает `Tab`.
_Сделать:_ проверить в игре; если `Tab` ходит по полям — писать пачкой с одним кликом и `Tab`
между полями. Решение и замер — в ADR.
_Проверка:_ диагональ 0.86 → ~0.6 с; поля на месте, проверка записи не ослаблена.
_Оценка:_ M. _Риск:_ высокий (зависит от поведения панели в игре).

_Статус:_ 🟡 оценено в 1.27.0, включение отложено — `ADR-0054`: замер пауз (запись поля 0.19 с,
сверка 0.16 с, диагональ 0.86 с = чтение позы + два поля) показывает, что выигрыш даёт только
переход `Tab` по полям панели, а его в игре не подтвердить из этой среды. Включение — после
проверки по шагам из ADR; до тех пор вместо ускорения появились метрики фаз (пункт 22).

**10. Раскладка под масштаб Windows.** На 200 % вкладке нужно 728 px при 703 видимых; в мини-версии
не хватает 43 px — третий переключатель уезжает под сгиб.
_Сделать:_ высота окна = `sizeHint` вкладки + шапка/статус (с ограничением по экрану), в
мини-версии — сетка переключателей 2×2 или рост до 380×470; подсказки — сворачиваемые.
_Проверка:_ тест «ни один виджет не за краем» при 100, 125, 150, 200 %; скриншоты пересобраны и
показывают строку режимов целиком.
_Оценка:_ M. _Риск:_ низкий.
_Статус:_ ✅ выполнено в 1.25.0 — `needed_height()` + рост окна (`_grow_to_fit_height`,
`fit_to_content`) с ограничением по экрану; мини-версия дорастает вместо обрезки третьего
переключателя; тест «ничего не за краем» на 9/11/14/18 пт (100–200 %); скриншоты пересобраны и
показывают строку режимов целиком.

**11. Видно, какой режим включён.** «Прямой шаг 4/6/8/2» меняет смысл клавиш, но на крестовине об
этом ничего: подпись режима говорит только про высоту.
_Сделать:_ строка режима перечисляет активные режимы (`высота · прямой шаг`), при включении —
короткая подсветка.
_Проверка:_ тест на текст строки при всех комбинациях; скриншот.
_Оценка:_ S. _Риск:_ низкий.
_Статус:_ ✅ выполнено в 1.25.0 — строка режима перечисляет активные («Включено: высота · прямой
шаг») и подсвечена, пока режим включён; тест на все четыре комбинации.

## Чего делать не стоит

- **Переписывать интерфейс на Qt Quick.** Нынешний QWidget-интерфейс рисуется за 0.15 с вместе с
  импортом, а весь выигрыш Qt Quick — в анимациях, которых здесь нет.
- **Добавлять сетевые функции и телеметрию.** Оверлей ценен тем, что работает локально; любая
  отправка данных — новый риск и новая строка в SECURITY.md.
- **Хранить состояние в базе.** Два JSON-файла переносятся копированием папки и читаются глазами;
  SQLite этого не улучшит.
- **Автоматизировать ввод через API игры.** Оверлей работает поверх интерфейса LSP специально:
  никаких внедрений в процесс игры.
