# Как мы работаем над Mapper's Overlay Redux

Документ фиксирует правила из `docs/instruction-code-style-and-checks.md` и трёх томов команды
(«Инженерный стандарт», «Настольная книга UI/UX», «README под ключ») применительно к этому
проекту: что проверяется автоматически и что считается «готово».

## Ветки и коммиты

- `main` — защищённая ветка: только через pull request, с зелёным CI.
- Рабочая ветка — от `main`, имя по смыслу изменения: `feature/always-read-pose`, `fix/step-locale`.
- Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`, `perf:`.
  Ломающее изменение — `feat!:` с объяснением в теле.
- В сообщении — смысл и причина изменения, а не перечисление файлов.
- История не переписывается: `force-push` в общие ветки запрещён.

## Локальный запуск

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pre-commit install      # хуки = проверки CI, но до коммита
.venv/bin/python main.py          # запуск окна
.venv/bin/python main.py --check-only
```

## Definition of Done

Задача закрыта, только если:

- `pre-commit run --all-files` чистый — то есть `ruff format --check .`, `ruff check .`,
  `mypy` (strict, Python 3.12) и проверки документации пройдены;
- `bandit -q -c pyproject.toml -r map_overlay tools` без замечаний, `detect-secrets-hook`
  по `git ls-files` — без находок, `pip-audit` — без уязвимостей,
  `python -m tools.check_licenses` — без сильного копилефта;
- `pytest` зелёный, покрытие `map_overlay` не ниже 80 %, критичные модули
  (`domain/movement.py`, `domain/formatting.py`, `application/writer.py`,
  `application/session.py`) — 100 % по ветвям, насколько это достижимо;
- на каждый исправленный баг добавлен регрессионный тест;
- обновлены `CHANGELOG.md` и README, если изменилось поведение для пользователя; строка
  «Версия — X.Y.Z» в README совпадает с `map_overlay/__init__.py` (это проверяет CI);
- значимое решение описано в `docs/adr/` по шаблону `docs/adr/0000-template.md` — с контекстом,
  вариантами, решением, последствиями, владельцем и датой пересмотра;
- если изменился интерфейс — пересобраны картинки: `python -m tools.make_screenshots`
  (вкладки и мини-версия) и `python -m tools.make_icons` (иконка);
- новая ошибка/тупик занесены в `docs/LESSONS.md`;
- нет мёртвого кода, закомментированных блоков, `TODO` без тикета и владельца, магических чисел.

## Pull request

- Размер — до 300–400 строк изменений; больше — дробить до ревью, а не после.
- Шаблон PR заполняется целиком и отвечает на пять вопросов: **что, зачем, как проверено,
  риски, откат**. Шаблон — `.github/pull_request_template.md`.
- Ревьюер смотрит корректность, читаемость, тесты, безопасность, ошибки, совместимость и
  документацию (чек-лист — в шаблоне PR).
- Замечание — предложение, а не приказ: автор отвечает на все комментарии («принято»,
  «исправлено», «обосновано»), но не игнорирует.
- Мерж только с зелёным CI и закрытыми блокирующими замечаниями. Красный CI не обходится
  «ещё одним коммитом»: сначала причина.

## Исключения из правил

Отступление от стандарта допустимо, если оно записано в
[docs/quality/exceptions.md](docs/quality/exceptions.md): правило, место, причина, владелец,
срок и статус. Просроченное исключение ломает CI — так «временное» не становится вечным.
Утверждает исключение владелец зоны из `.github/CODEOWNERS`.

## CI и гейты

`.github/workflows/ci.yml` на Python 3.12 прогоняет: pre-commit (формат, линтер, типы,
документация, исключения), тесты с покрытием, `bandit`, `pip-audit`, проверку лицензий
(`tools/check_licenses.py`), поиск секретов (`detect-secrets-hook` по `git ls-files`),
проверку документации (`tools/check_docs.py`), политику исключений
(`tools/check_exceptions.py`), сборку колеса и SBOM (`tools/make_sbom.py`, артефакт `build/`).
PR без зелёного CI не мержится.

## Документация

- `README.md` — витрина для пользователя: что это, зачем, как запустить, как выглядит. Структура
  и обязательные разделы проверяются в CI; картинки собираются командами
  `python -m tools.make_screenshots` и `python -m tools.make_icons`.
- `docs/adr/` — решения с контекстом и последствиями; у каждого есть владелец и дата пересмотра.
- `docs/LESSONS.md` — памятка: ошибка → причина → как не повторить.
- `docs/quality/exceptions.md` — отступления от стандарта с владельцем и сроком.
- `CHANGELOG.md` — только пользовательские изменения, SemVer.
- `SECURITY.md` — приватный канал для уязвимостей и сроки ответа.
- `docs/instruction-code-style-and-checks.md` — исходная инструкция, менять её нельзя.

## Перед каждой версией

1. Прогнать все проверки из Definition of Done и CI-набор целиком.
2. Перечитать `docs/LESSONS.md` и сверить код: не повторяем ли уже пройденный тупик.
3. Проверить, что документация соответствует коду (README, ADR, CHANGELOG), и поднять версию в
   `map_overlay/__init__.py`, `pyproject.toml`, README и `CHANGELOG.md`.
4. Собрать архив релиза `Mappers_Overlay_Redux_vX.Y.Z.zip` (только `git ls-files` +
   `zip -qr -X -D`), распаковать в чистую папку, запустить `--check-only` и тесты — только
   потом коммит и тег.
