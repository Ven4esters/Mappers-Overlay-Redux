# Стиль кода

Инструменты решают споры: `ruff format` (Black-совместимо, 100 символов),
`ruff check`, `mypy --strict`, Python 3.12.

## Пороги, которые проверяет линтер

- функция — до 30–40 строк, вложенность — до 3–4 уровней;
- цикломатическая сложность — до 12 (стандарт допускает 10–15): `ruff` `C901`;
- ветвлений в функции — до 12, операторов — до 50: `PLR0912`, `PLR0915`;
- параметров — до 5, линтер настроен на 7 (`PLR0913`): исключение для конструкторов с
  внедрением зависимостей записано в `docs/quality/exceptions.md`;
- `# noqa` и `# nosec` — только с причиной рядом; исключение, которое живёт дольше одной
  задачи, идёт в политику исключений с владельцем и сроком.

## Именование

- классы и типы — `PascalCase`, функции и переменные — `snake_case`,
  константы — `UPPER_SNAKE_CASE`;
- булевы — `is_`, `has_`, `can_`, `should_`;
- без сокращений, кроме общепринятых (`id`, `url`, `px`, `dpi`);
- файлы и пакеты — по смыслу (`panel_automation.py`, а не `utils2.py`).

## Функции

- до 30–40 строк, вложенность до 3–4 уровней, сложность ≤ 10–15;
- одна ответственность, явные аргументы, никаких скрытых зависимостей;
- публичные функции и классы — с docstring по Google-стилю;
- магические числа — в именованные константы с единицами (`CLICK_DELAY_S`);
- «висячий» литерал после константы (`X = 1` и `"""пояснение"""` ниже) — не документация:
  пишите комментарий `#` рядом с константой;
- мёртвый код удаляется, а не комментируется: `# noqa`/`# nosec` — только с причиной
  рядом и только там, где иначе нельзя.

## Слои

```
ui/            PySide6: окна, вкладки, стили. Знает про application, не про Win32.
application/   сценарии: сессия, запись, порты. Не знает про Qt и ctypes.
domain/        чистая логика: поза, направления, форматирование. Без I/O.
infrastructure/ Win32, буфер обмена, файлы настроек. Реализует порты.
```

Горячие клавиши разложены так же: `Action` и `keynames` — домен, `HotkeyRouter` —
приложение, `WindowsHotkeySource` — инфраструктура.

Зависимости идут только внутрь: `ui → application → domain`,
`infrastructure → application/domain`. Домен ничего не импортирует из соседних слоёв.

## Ошибки и логи

- своя иерархия от `AppError`: `DomainError` → `ValidationError`, `ParseError`;
  `ConfigError`; `ApplicationError` → `NotCalibratedError`, `PoseNotCapturedError`,
  `PanelRejectedError`, `CursorMovedError`, `InputError`, `ClipboardError`,
  `UnsupportedPlatformError`;
- в UI показываем текст для пользователя, в журнал пишем контекст;
- исключения не глотаем: либо обрабатываем, либо пробрасываем с контекстом;
- логи — JSON-строки с уровнем и именем логгера, без секретов и координат мыши;
- в потоке хука клавиатуры — никакого дискового ввода-вывода: там допустим только
  `DEBUG` (`INFO` в этом потоке задерживает клавишу);
- журнал и файл аварий ограничены по размеру (`RotatingFileHandler`, поворот `crash.log`).

## Интерфейс

Правила из «Настольной книги UI/UX», которые проверяются автоматически (`tests/test_theme.py`)
или видны в коде:

- цвета и отступы — только из `ui/theme.py` и константы `ui/widgets.py`; «сырых» hex-кодов в
  обработчиках нет;
- контраст основного текста — не ниже 4,5 : 1, крупного — 3 : 1; текст ошибки — `DANGER_TEXT`,
  а не цвет заливки `ERROR`;
- фокус виден всегда: в QSS есть `:focus` для кнопок, полей и списков;
- зона клика — не меньше 24 × 24 px на десктопе; у стрелок крестовины она задана в коде
  (`ARROW_MIN_WIDTH`, `ARROW_MIN_HEIGHT`), а не только стилем;
- у кнопки-значка есть доступное имя (`setAccessibleName`), а подсказка становится описанием;
- абсолютного позиционирования (`setGeometry`) нет: раскладку задают менеджеры компоновки;
- тяжёлая работа — в отдельном потоке, окно не замирает.

## Тесты

- unit — на домен (математика направлений, форматирование, разбор чисел);
- integration — на автоматизацию панели через фейковый ввод и буфер: проверяется порядок
  «клик → Ctrl+A → Ctrl+C» и запись «буфер → клик → Ctrl+A → Ctrl+V»;
- UI — smoke-тесты на offscreen-платформе;
- тесты детерминированы: время и мышь — через фейки, без `sleep` в тестах.
